# hatch-shelf · 书巢

个人自用的 iOS 离线 Markdown 书架。AI 在电脑上写书，通过 AirDrop 或局域网传到手机，在本地存储与管理，离线阅读。

- **Bundle ID**：`com.jarvis.shelf`
- **显示名称**：书巢（内部名 `Shelf` 仍用于 Xcode 工程与 scheme）
- **平台**：iOS（Expo / React Native，保留以后出 Android 的可能）

---

## 1. 目标与非目标

**目标**

- 把 AI 产出的技术类、知识类内容组织成“书”，在手机上获得舒适的离线阅读体验
- 导入路径尽量短：AI 写完 → 一条命令或一次 AirDrop → 手机上可读
- 内容格式不绑定任何 AI 服务，任意 agent 遵守书库仓库的 `AGENTS.md` 即可写书

**非目标（当前阶段）**

- App 不联网：不做云同步、不做账号、不做热更新
- 不做编辑器：手机端只读，内容的生产在电脑端
- 不上架 App Store：通过开发者账号自装或使用 TestFlight

---

## 2. 整体架构

```
[任意 AI Agent] → 书库 books/ ─┬─ [Dock 网页] ── 局域网推送 ──┐
                               └─ AirDrop / 分享 (.zip/.md) ──┤
                                                         ↓
                                App: inbox/ → 校验 → books/ → SQLite 索引
                                                         ↓
                                                     离线阅读
```

**核心原则**

1. **文件即真相**：书籍原文以文件形式存放在 `documentDirectory/books/`，SQLite 只存索引和用户数据
2. **导入只是“往 books/ 放东西”**：所有通道共用同一条导入管线；阅读器只认 `books/` 目录
3. **索引可重建**：`books` 和 `chapters` 两张表随时可以通过扫描目录重建；阅读进度与设置不可丢

## 3. 仓库结构

两个仓库放在同一个父目录下：本仓库（代码，公开，pnpm workspace）和书库 `hatch-shelf-library`（内容，私有）。

```
hatch-shelf/
├── README.md
├── AGENTS.md              # 代码侧规范（开发 App / CLI 时 agent 读取）
├── pnpm-workspace.yaml
├── apps/
│   ├── mobile/            # @shelf/mobile：书巢 iOS App（Expo，Metro 根目录在此）
│   │   └── samples/       # 随安装包发布的 2 本示例书，也是测试用的书
│   └── dock/              # @shelf/dock：电脑端控制台，本地 Node 服务 + 网页，读书库、和手机比对、推送
├── packages/
│   ├── spec/              # @shelf/spec：book.yaml 的 zod schema + TS 类型，App 与 CLI 共用
│   ├── reader/            # @shelf/reader：阅读器网页，打包成单个 HTML 放进 App
│   └── library/           # @shelf/library：依赖 Node 的书库逻辑 + shelf-pack 命令行
└── design/                # App 的 UI 设计稿（pen.dev），不进安装包
    ├── 设计稿.pen
    ├── covers/ images/    # 设计稿引用的图（UI 插图、书封）；书封的原稿在书库的 封面.pen
    └── splash/            # 启动流程画面

hatch-shelf-library/       # 纯数据仓库：没有代码和依赖，命令都在本仓库运行
├── AGENTS.md              # 写书规范和书库命令（CLAUDE.md 指向它）
├── books/<分组>/<书名>/    # 一本书：book.yaml、中文名的章节、assets/、audio/（原声，Git LFS）、notes.md（阅读笔记）
└── design/                # 封面设计稿 封面.pen + images/ 插画原图
```

**提交约定**：代码提交使用 Conventional Commits（`feat:` / `fix:` / `chore:` …）；书库里内容提交使用 `content:` 前缀。

**为什么拆成两个仓库**：书写到近百本后，内容提交占了一半以上，git 历史里书和封面原图约 160 MB、代码只有 4 MB；原声录音有 4 GB，只放在本机没有备份。拆开后书库可以设为私有、用 Git LFS 管录音，代码仓库保持轻量。拆分时用 `git filter-repo` 带着历史导出了 `books/`、`notes/` 和封面原图，本仓库没有改写历史。

## 4. 内容规范

### 4.1 目录结构

```
books/技术/Go 并发编程实战/      # 书库里：books/<分组>/<书名>/，分组是 category 的第一段
├── book.yaml
├── cover.png                # 可选；缺省时 App 自动生成文字封面
├── 01-goroutine-是什么.md    # 章节文件名可以用中文，不能有空白和 / \ : * ? " < > | # %
├── 02-channel.md
├── assets/                  # 本书的全部图片
├── audio/                   # 只在书库里：原声（8.1），不进书包
└── notes.md                 # 只在书库里：从手机导出的阅读笔记
```

- **书库给人看，手机给机器用**。书库里目录是 `<分组>/<书名>`（书名里的 `/` `\` `:` 换成全角），跨书引用按路径写；手机上书平铺在 `books/<id>/`。`shelf-pack pack` / `push` 打包时翻译一次（`@shelf/spec` 的 `deviceLinks()` / `deviceNext()`），App 和阅读器只认手机上的写法
- 书库里的 id 是 UUID（`shelf-pack new` 生成），只给机器用，永远不改；改书名、换分类用 `shelf-pack mv`。App 只要求 id 是 `[a-z0-9-]`，App 自带的示例书仍用 `shelf-guide` 这样的 id

### 4.2 book.yaml

```yaml
id: 3f2a9c1e-7b4d-4c2a-9f1e-0a1b2c3d4e5f   # 必填，[a-z0-9-]，书库里用 UUID；同 id 再次导入即为更新
title: Go 并发编程实战          # 必填
subtitle: 从 goroutine 到调度器  # 可选
category: 技术/Go             # 可选，书架分组，用 / 分层
tags: [go, concurrency]       # 可选
level: intermediate           # 可选：beginner | intermediate | advanced
created: 2026-11-02           # 可选
updated: 2026-11-02           # 可选
chapters:                     # 必填，显式排序
  - 01-goroutine-是什么.md
  - 02-channel.md
next:                         # 可选，读完后接着读的书，最多 3 本
  - book: 技术/Go 运行时        # 书库里写路径，打包时换成 id: <那本书的 id>；App 只认 id
    reason: 接着看调度器怎么安排 goroutine   # 可选，一句话（≤ 60 字），缺省时用那本书的副标题
```

`next` 是阅读路线的一部分，跟着书走而不是写死在 App 里：80 多本书的 `next` 按 `reading-map` 的阅读路线写，新书加入路线时只改 book.yaml。

### 4.3 写书硬规则（同步写入书库的 AGENTS.md）

- 每章一个 `.md` 文件，以唯一的 H1 作为章标题
- 图片只能引用 `assets/` 下的相对路径，**禁止远程图片**（离线时无法显示）
- 章节与书之间的引用写成相对链接：`03-x.md#锚点`（本书）；另一本书在书库里写 `<../../<分组>/<书名>/03-x.md#锚点>`，打包后是手机上的 `../<id>/03-x.md#锚点`。解析规则是 `@shelf/spec` 的 `parseLibraryLink()` / `parseBookLink()`
- 图表用 Mermaid（流程、结构类）或 `assets/` 下的 SVG（数据图、坐标图、示意图），**禁止在代码块里用字符画图**；SVG 的底板、尺寸、字体、配色规范见书库的 `AGENTS.md`「配图」
- 代码块必须标注语言
- 数学公式使用 KaTeX 语法（`$...$` / `$$...$$`）
- 章节文件名用两位序号加标题，可以用中文（`01-为什么需要-RAG.md`），不能有空白和 `/ \\ : * ? " < > | # %`；图片文件名仍用 `[a-z0-9-]`
- 法规、财税、版本敏感的内容加 `> [!WARNING]` 提示块，写明以官方最新规定为准；提示块的写法见书库的 `AGENTS.md`

### 4.4 容错

| 输入 | 处理 |
|---|---|
| 目录缺少 `book.yaml` | 用目录名作为 id 和标题，章节按文件名排序 |
| 单个 `.md` 文件 | 包装成单章书，id 取自文件名 |
| `chapters` 列出的文件不存在 | 跳过该章，并在书籍信息里提示 |
| 存在但未列入 `chapters` 的 `.md` | 忽略 |

## 5. 导入通道

### 5.1 AirDrop / 系统分享

- 在 `CFBundleDocumentTypes` 中注册 `.zip` 和 `.md`
- 选择“用书巢打开”后，文件进入导入管线
- 书架右上角的“导入”可以从“文件” App 里选一个 zip / md，走同一条管线

### 5.2 局域网推送：Dock 与接收模式

电脑上运行 Dock（`pnpm dock`，`apps/dock`），在浏览器里打开 `http://localhost:5170`：左侧按状态、分组筛选，右侧以封面墙列出书库里的每一本书，和手机比对后的状态写在封面角标上；点封面勾选，从底部浮条一次推送。手机上进入「接收模式」，只负责确认推送、看着书进来。设计稿见「Dock · 电脑端控制台」和「书巢 · 接收模式（配合 Dock）」。

**配对**：第一次在 Dock 里点「连接手机」，弹出二维码，内容是 `shelf://pair?k=<密钥>&name=<电脑名>`（开发版 App 的 scheme 是 `shelf-dev`，启动时 `SHELF_APP=dev pnpm dock`）。用 iPhone 系统相机扫码会拉起书巢；书架「+ → 从电脑接收」在还没配对时也会进 App 内的扫码页（`expo-camera`）。密钥是 Dock 随机生成的 16 字节，扫码后两边长期保存：手机存在 settings 的 `pairedComputers`（不进阅读数据备份），设置页「电脑」里可以取消配对；Dock 存在浏览器的 localStorage。之后每次只要在手机上打开接收，Dock 就会自己连上。Dock 同一时间只连一台手机，换手机要先在 Dock 上断开（见下方 Dock 一节）。

**发现**：手机仍只做服务端，不主动发请求。Dock 先试上次连上的地址和 127.0.0.1（模拟器），再并发扫描本机所在 /24 网段的 `:8080/ping`，找到回应的书巢后用密钥调 `/hello` 确认。

**接收模式**（`apps/mobile/src/receive/`）：
- 入口是书架「+」菜单的「从电脑接收」、空书架的按钮，或扫码。进入即开始监听，不再有单独的「开启」
- 状态放在模块里（`store.ts`），不属于某个页面：接收页（`app/receive.tsx`，可下滑收起）收起后服务继续运行，App 根部的 `ReceiveHost` 在所有页面顶部挂一个胶囊显示进度，点它回到接收页、点 × 结束；胶囊和接收页互斥。接收期间屏幕常亮
- Dock 每次推送先发 `/session/request`，手机上从底部升起确认框，列出要推的书和预计大小；点「开始接收」才传输，点「拒绝」Dock 回到列表。不在接收页时自动打开接收页。同一时间只接受一次推送，传输期间新的请求返回 409
- 收到的书逐本列在接收页，同一本书的书本身和原声合成一行；Dock 拉笔记、做备份也记一行。Dock 推完发 `/session/end`，接收页显示汇总（新书 / 更新 / 原声章数），8 秒后自动结束；5 分钟没有任何请求也自动结束
- App 进入后台时 iOS 会挂起服务，回到前台时重新监听，进行中的推送状态保留

**Dock**（`apps/dock`）：
- `server/` 是只监听 127.0.0.1:5170 的 Node 服务，提供网页和 `/api`；只认本机的 Host，非 GET 请求还要校验 Origin，防止别的网页借浏览器调用。书库路径、配对密钥、手机地址都存在浏览器的 localStorage，随请求头带给服务端，服务端不落盘
- 书库路径没有默认值，首次打开用系统的「选择文件夹」对话框选（顶栏「更换」也一样），选中后立即检查能找到几本书；书库仓库根目录或其中的 `books/` 都行。浏览器的 `showDirectoryPicker` 只给句柄、拿不到真实路径，所以对话框由本机服务用 `osascript` 的 `choose folder` 弹出（`POST /api/pick-folder`）；不是 macOS 时退回手填路径
- 每本书的状态：校验未通过（`lintBook()` 报错，不能勾选，点开看错误）、新书、有更新（内容指纹不同）、已同步；书库里录好原声的书在封面右上角标「原声」（与手机书架的角标一致，列表视图标在书名后），手机上缺几章原声写在书名下方；另外标出手机上有几条还没写回书库的笔记。书库里没有、手机上有的书列在「仅手机有」，只显示不删除
- 推送：服务端按手机当前的状态重新算一遍每本书要传什么（书的 zip、缺的原声章节），发确认请求，确认后串行上传，网页每 400ms 轮询进度。封面上原地显示进度，底部浮条显示总进度和「停止」
- 同一时间只连一台手机（设计稿 ⑧）。还没连手机时顶栏是「连接手机」，点开扫码；第一次连上后记下这台手机的名字（localStorage），顶栏固定显示它的状态：已连接（名字和地址）、等待打开接收、手机上已取消配对。点开是手机菜单，只有「断开连接」，在菜单里原地确认。断开时手机在线就发 `/bye`（同时停止正在进行的推送），手机删掉这台电脑的配对并结束接收；Dock 清掉密钥和手机名字，回到「连接手机」。换手机就是先断开，再扫码。手机不在线时断开只清 Dock 这边，手机上的记录在「设置 → 电脑」里删
- 连上手机后网页通过 `/api/phone/watch` 一直挂着手机的 `/watch`：手机上点「结束」、倒计时结束或空闲结束时，顶栏立即变成「等待 … 打开接收」，不等下一次 20 秒的刷新；连接断了（手机被挂起、断网）也一样处理，之后照常每 3 秒找一次手机
- 一次性的结果（推送完成 / 被拒绝 / 中断、拉取笔记、备份、切换书库、断开连接）都用顶栏下方居中的 Toast 显示（设计稿「⑥ 通用 Toast」），成功和提示 4 秒、失败 6 秒后消失；底部浮条只显示需要操作的状态（等待确认、推送中），推送结束后立即回到平时的样子，被拒绝时保留勾选
- 新书的封面缩略图由 Dock 用 macOS 的 `sips` 缩到 132px 宽（JPEG），按文件修改时间缓存；不是 macOS 或书没有封面时不带，手机上按分类画文字封面
- 「拉取笔记」把手机上的笔记写到书库各书目录的 `notes.md`，只差导出日期的不重写；「备份阅读数据」把手机上的备份 JSON 直接下载到浏览器
- 书库扫描按书目录的最近修改时间缓存打包结果，96 本书首次约 2 秒，之后不到 0.3 秒

**接口**（手机端，协议类型在 `@shelf/spec` 的 `transfer.ts`，除 `/ping` 外都要带 `Authorization: Bearer <密钥>`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/ping` | 不需要密钥；返回 `{ ok, app: 'shelf', protocol }`，Dock 扫网段时用它认出书巢、判断协议版本 |
| GET | `/hello` | 校验密钥，返回手机名字（见下方「手机名字」）；密钥不对时 401 |
| GET | `/watch` | 挂着不返回，手机结束接收时立即返回 `{ ok, receiving: false }`，25 秒内没变化返回 `receiving: true`；不算「有动作」，不影响空闲自动结束 |
| GET | `/books` | 本地书籍的 id、标题、更新时间和内容指纹 `hash` |
| GET | `/audio/<id>` | 这本书在手机上的原声清单，Dock 据此只推缺的章节 |
| GET | `/notes` | 每本有高亮的书的笔记：`{ id, title, count, markdown }`，`markdown` 与分享导出的 `<id>.notes.md` 相同 |
| GET | `/backup` | 阅读数据备份（见第 7 节） |
| POST | `/session/request` | `{ items, bytes }`，挂起直到手机上确认或拒绝，返回 `{ ok, accepted }`。新书的 item 带分类和封面缩略图（`cover`，JPEG data URI，不超过 64 KB），确认框里据此画封面 |
| POST | `/session/log` | `{ kind: 'notes' \| 'backup', detail }`，接收页记一行 |
| POST | `/session/end` | 这次推送结束 |
| POST | `/bye` | Dock 上点了「断开连接」：手机删掉这台电脑的配对，结束接收模式 |
| POST | `/upload` | `multipart/form-data`，字段 `file`；只在确认过的推送里接受，成功时返回 `status`（`added` / `updated` / `audio`）、`title`、`chapters` 和 `warnings` |

**手机名字**：iOS 16 起，读用户自己起的设备名（「某某的 iPhone」）需要 Apple 审批的 `user-assigned-device-name` 权限，否则只能拿到「iPhone」。所以 `/hello` 在拿不到自定义名字时返回机型名（`expo-device` 的 `modelName`，如「iPhone 16 Pro」）。没按这个依赖重新构建的 dev client 里没有原生模块，这时回退成「iPhone」。

**限制**：单个文件不超过 50 MB（原声按章分包）。

**实现**：HTTP 解析在 `apps/mobile/src/server/http.ts`（纯函数，Node 中测试），只支持带 `Content-Length` 的请求，每个连接处理一个请求后关闭；Dock 用 `node:http` 自己拼 multipart，保证有 Content-Length，并按发出的字节报告上传进度。上传的文件落成临时文件后交给第 6 节的导入管线，多个上传串行导入。

### 5.3 “文件” App 可见（可选，M4 之后）

开启 `UIFileSharingEnabled` 和 `LSSupportsOpeningDocumentsInPlace`。外部增删书目录或更新 `.content-hash` 后，App 在冷启动后的后台对账里修正这些书的索引；书内文件被直接改动时到设置页点「重建索引」，全量重新扫描。

## 6. 导入管线

所有通道走同一条管线：

实现：判断与转换在 `@shelf/spec` 的 `prepareImport()`（纯函数，App 与 CLI 共用），落盘与索引在 `apps/mobile/src/import/pipeline.ts`。

1. 文件落到 `inbox/<uuid>/`
2. 安全校验
   - 解压时防止 zip slip：拒绝绝对路径和包含 `..` 的条目
   - 只放行这些扩展名：`.md` `.yaml` `.yml` `.png` `.jpg` `.jpeg` `.gif` `.webp` `.svg`
   - 检查单个包大小
3. 用 `@shelf/spec` 解析并校验 `book.yaml`，或按第 4.4 节的容错规则处理
   - zip 里可以直接放书的文件，也可以外面再套一层书目录；`__MACOSX/`、`.DS_Store` 直接丢弃
   - 走容错规则时补写一份 `book.yaml`，让设备上的目录名、id、标题在之后重建索引时保持一致
4. 原子写入：先完整写到 `books/.tmp-<id>/`，再整体替换 `books/<id>/`（旧目录先改名为 `.old-<id>/`，新目录就位后删掉）。替换中途被杀时，下次启动把 `.old-<id>/` 改回原名，并清掉残留的 `.tmp-<id>/`
5. 同 id 更新时：保留仍然存在的章节的阅读进度，删除已不存在章节的进度
6. 更新 SQLite 索引，清理 `inbox/`
7. 向用户反馈结果（新增 / 更新 / 失败原因）

所有通道共用一个串行队列（`importFile` 内部排队），一次只导入一个文件；某次导入失败不影响后面排队的文件。

## 7. 本地存储

```
documentDirectory/
├── books/<id>/      # 书籍原文
├── inbox/           # 导入临时区
└── shelf.db         # SQLite
```

| 表 | 字段 | 可重建 |
|---|---|---|
| books | id, title, subtitle, category, tags(JSON), level, chapter_count, warnings(JSON), imported_at, updated_at, content_hash, last_read_at | ✅ |
| chapters | book_id, idx, file, title, hash（章节内容指纹） | ✅ |
| search（FTS5，trigram） | book_id, chapter_file, anchor, heading, body —— 每行一个小节 | ✅ |
| progress | book_id, chapter_file, scroll_ratio, anchor, updated_at, seen_hash（读这一章时的内容指纹） | ❌ |
| settings | key, value | ❌ |
| highlights | id, book_id, chapter_file, text, prefix, suffix, anchor, kind（`highlight` / `doubt`）, note, created_at, updated_at | ❌ |

`last_read_at` 由 `progress` 推导；重建索引时从 `progress` 回填。

**备份**：不可重建的三类数据（progress、highlights、settings 里的外观与阅读设置）可以导出成一个 JSON（`apps/mobile/src/backup/`）。两条路：设置页「备份阅读进度与笔记」经分享面板存到「文件」或 AirDrop，「从备份恢复」从「文件」选回来；或者在 Dock 里点「备份阅读数据」下载到电脑。恢复是合并：本机没有的写入，两边都有的保留 `updated_at` 较新的一份，所以不会冲掉备份之后的新记录（备份之后删掉的高亮会被恢复回来）。书的原文不在备份里，换机后重新推书，进度和高亮按书 id 与章节文件名挂回去。

## 8. 阅读体验

**界面**

- 视觉稿是 `design/设计稿.pen` 的「晨雾玻璃」：磨砂玻璃卡片、顶部晨雾配图、色彩只来自封面；设计 token 在 `apps/mobile/src/ui/theme.ts`，亮色取自设计稿，暗色按同一结构压暗
- 底部玻璃 Tab：书架 / 笔记 / 设置（传书改为书架「+」里的接收模式，见 5.2）。外观（亮色 / 暗色 / 跟随系统）在设置页切换，对整个 App 和阅读器生效
- 冷启动先显示与书架同底色的原生纯色启动图，数据就绪后直接淡入书架（200ms）。开场封面只在安装后第一次启动时播放：封面淡入、停留到数据加载完，再与书架交叉淡化；轻点可跳过
- 轻动效遵循设计稿「轻动效」：位移 ≤ 12pt、缩放 ≥ 0.96，系统开启「减弱动态效果」时降级为短淡入淡出；阅读页内不放环境动效
- 进书和切章不显示加载指示（设计稿「进书 · 版式占位与显影」）：阅读器渲染完成（`rendered`）前，由 `apps/mobile/src/reader/PagePlaceholder.tsx` 按 `packages/reader` 的 CSS 版式画出章号、章标题和静止的淡墨行，渲染完成后原地淡出 240ms；从章节中间继续时不画标题。改了阅读器的正文边距、字号比例后要同步改占位
- 界面不放阅读时长、连续天数之类的统计

**书架**

- 按 `category` 的第一段分系列，原样显示为系列名（如 `人工智能/Agent` 归入「人工智能」），App 不维护映射；系列按其中最早导入的书排序，未分类最后。每组横向滚动，「全部」进入该系列的网格；顶部放“继续阅读”卡片（最近读过、还没读完的一本）
- 封面左下角显示进度：读完显示 ✓，读过显示百分比。书的进度按「已读章节数 + 当前章节滚动比例」估算
- 封面是书库 `design/封面.pen` 里的原稿导出（600×856），复古丝网印刷风插图 + 每本一个主色，底部统一署名「Jarvis」；没有封面时，按「书架文库」版式用标题、副标题和分类色自动生成文字封面，署名相同
- 点按书籍直接进入阅读页，回到上次读到的位置；「继续阅读」卡片也一样
- 长按书籍进入书籍详情（原来的长按预览和详情页合并为一页，设计稿「v11 · 书籍详情」与「长按 · 进详情过场」）：按下封面缩到 0.96 并略压暗，满 300ms 中等触感；封面抬到 1.15 倍、书架模糊变淡，随后用弹簧（阻尼比 0.85）飞到详情页的大封面，返回时飞回书架上此刻的位置（`apps/mobile/src/ui/CoverFlight.tsx`）。300ms 内松手按点按处理，按住时滑动则取消
- 书籍详情以封面为主：封面宽取屏幕宽减 60 与可用高度中较小者，左上角返回、右上角「···」（导出笔记、从书架删除）；封面下方是横向滑动的章节卡，默认滚到在读的一章（在读卡加宽并显示本章进度，读过的变淡打勾），没读过的书第一张写「从这里开始」；底部「继续阅读 / 开始阅读 / 重新阅读」和「笔记」。「全部」从底部弹出完整目录，分类、难度、更新日期和导入提示也写在这里；删除确认里有笔记时先提供「先导出笔记」
- 书架标题旁显示书的总数，各系列标题旁显示该系列的本数

**全文搜索**

- 书架右上角的搜索进入全文搜索页；结果按书分组，显示章节、小节和关键词附近的片段
- 索引按 H1–H3 切成小节（`@shelf/spec` 的 `splitSections()`），与 books / chapters 一起在重建索引时生成
- 3 个字符及以上用 FTS5 trigram 匹配并按相关度排序；更短的查询（如两个汉字）退回 `LIKE` 扫描
- 点击结果打开对应章节，跳到小节锚点，并标亮锚点之后第一处匹配。标题锚点算法（`createSlugger()`）由阅读器与索引共用，保证一致

**阅读器**（WebView 渲染）

- 渲染库：markdown-it + highlight.js + KaTeX + Mermaid，**全部打包进 App，不走 CDN**
- 目录：从左侧滑入的抽屉，当前章节展开 H2 / H3，并标出视口所在的小节
- 阅读进度：记录滚动比例和最近的标题锚点，进入章节时自动恢复
- 主题跟随 App 外观，阅读页不单独设主题；字号（14–24，六档）和行距（紧凑 / 适中 / 宽松）可调
- 代码块：默认横向滚动，可切换为自动换行；提供一键复制
- 宽表格放在可横向滚动的容器里；图片支持点击放大
- 提示块：GitHub 风格的 `> [!NOTE]` / `[!TIP]` / `[!IMPORTANT]` / `[!WARNING]` / `[!CAUTION]` 渲染成带图标和中文标题（注意 / 提示 / 重要 / 警告 / 当心）的彩色卡片，颜色取自阅读器现有的主题变量，亮色暗色各一套；实现是 `packages/reader/src/callouts.ts` 里的 markdown-it 插件，其余引用块照旧
- Mermaid：左右方向的流程图比屏幕宽时自动改成上下方向重新渲染；其余过宽的图缩到屏幕宽，不支持点按放大
- 阅读页只有两颗悬浮按钮：左上角返回，右上角「···」；目录、本章查找、本书笔记、阅读设置、听书都收在「···」菜单里。不提供上一章 / 下一章，换章走目录，底部不放任何东西（听书时的播放面板除外），正文铺满到屏幕底
- 接着读：最后一章正文之后，按本书 `book.yaml` 的 `next` 列出推荐的书（封面、书名、一句理由），点按与跨书链接一样在当前页之上打开那本书。已读完（`FINISHED_RATIO`）的书不再列出；书架上没有的书显示虚线封面和「需要先导入」，点按弹出同样的提示。卡片在 `#content` 之外，不参与高亮、搜索和目录；阅读进度按正文计算，卡片高度不计入，滚到正文末尾即为读完。App 打开最后一章时读取 book.yaml（`apps/mobile/src/reader/next-reads.ts`），不进 SQLite
- 本章查找：查找时顶部换成查找栏，在当前章节里不区分大小写地标亮全部匹配（复用搜索跳转的 `mark.find-hit`，与高亮 `mark.hl` 可互相嵌套），显示「第 i / n 处」，上一处 / 下一处首尾循环；匹配可跨加粗、链接等行内格式，不跨段落，不查公式和 Mermaid 图。点「完成」或换章即清除标亮
- 链接：`#锚点` 在页内滚动；`03-x.md#锚点` 切到本书对应章节；`../<id>/…` 在当前阅读页之上打开另一本书的对应章节和小节（只写书 id 时打开到上次读到的位置），返回即回到原书，目标书未导入时给出提示；`http(s)` 链接交给系统打开
- RN 与 WebView 之间通过 `postMessage` 通信，协议类型定义在 `apps/mobile/src/reader/bridge.ts`
- 高亮与笔记：长按选中文字，系统菜单里选「高亮」「笔记」或「存疑」，笔记在浮于键盘上方的面板里输入；点已有高亮可编辑笔记、标为 / 取消存疑或删除。存疑用于标出读者认为可能有错的地方：橙色底加波浪线，可以附一句说明；导出时单独放在最前面的「存疑」一节，供 agent 修订时优先核实（见书库的 `AGENTS.md`「读者笔记」）。「笔记」Tab 按书列出有高亮的书，阅读页「···」菜单里的「本书笔记」列出整本书的高亮，点一条跳回原文；可导出为 Markdown，经分享面板 AirDrop 回电脑，放到书库里那本书目录下的 `notes.md`；也可以在传书开启时用 `shelf-pack pull-notes` 一次拉回全部笔记
- 高亮定位不记字符偏移，而是记原文 + 前后各 32 字 + 所在小节锚点；重新打开或书更新后，在正文里找所有出现原文的位置，取前后文最吻合的一处（`packages/reader/src/highlights.ts`）。原文被改掉的高亮仍在笔记页里，只是在正文中不再显示
- 书更新时高亮保留；删除书时连同阅读进度、高亮一起删除（确认框会提示先导出）
- 书籍管理（设置 →「书库」→ 书籍管理，设计稿「书籍管理」）：专为批量删除。按系列分组，页面常驻勾选态，分类标题可整类勾选，右上角「全选」；选中后底部升起「删除 N 本 · 释放 X」，确认框里有笔记时先提供逐本「先导出笔记」。顶部圆环显示各系列占用：每本书的大小（`books/<id>/` 递归）异步统计，统计中一段彗星弧绕轨道旋转，每统计完一个系列对应色段扫入，图例、分组和每行的数字同步出现。结果按内容指纹缓存在 settings 的 `bookSizes`，下次进入直接显示，只补算新导入或更新过的书（`apps/mobile/src/library/sizes.ts`）
- 章节更新标记：读过的章节在书更新后内容变了，目录、详情页的章节卡和完整目录显示橙色的「已更新」，详情页目录标题旁写「N 章更新」；打开这一章即清除。依据是 `progress.seen_hash` 与 `chapters.hash` 不同，没读过的章节不标。升级到带这两个字段的版本后，第一次全量重建索引（`INDEX_VERSION` 2）会按当时的内容补上旧进度的 seen_hash
- 听书：「···」菜单里的「听书」用系统语音（`expo-speech`，即 AVSpeechSynthesizer）从视口里第一段开始读，读完一章自动接下一章，直到全书读完，完全在本机运行。段落由阅读器切好（规则在 `packages/reader/src/segment.ts`，`tts.ts` 负责收集和标记）：代码块、表格、Mermaid 和块级公式不朗读，只念一句「此处有代码，略过」之类的提示；行内公式短的念 TeX 原文，长的念「公式」。开始听书时连后面各章一起切好（渲染进 `<template>` 只取文本，编号与显示出来后一致），存在 RN 侧，App 在后台、WebView 被冻结时也能换章。一章一次排进系统朗读队列，本章最后一段开始时排进下一章，章与章之间不留空。每段开始时阅读器标出这一段，段落离开视口时滚到屏幕上方三分之一处，手动滚动后 5 秒内不跟随。读到下一章时记下进度；阅读页在前台就跟过去，在后台则等回到前台再加载那一章并滚到正在读的段落。朗读时屏幕底部升起整块播放面板（听书不要求沉浸，正文底部多留出面板的高度）：章节名、定时停止和停止；段落进度「第 N 段 · 共 M 段」，拖动进度条松手后跳到那一段（不显示剩余时间）；iOS 26 默认的全屏右滑返回会和进度条抢手势，听书时阅读页只保留左边缘右滑返回；语速（0.8 / 1 / 1.25 / 1.5 倍，记住上次的选择）、上一段 / 暂停或继续 / 下一段、语音。跳段时暂停中也直接开始读，阅读器总是滚到那一段。手动滚到正在读的段落离开屏幕后不再自动跟随，面板顶部出现「从这里读」，点一下重新切段、从屏幕上第一段接着读；滚回朗读位置后这一行收起。点面板上的语音打开「朗读语音」面板：默认「自动」，也可按普通话 / 台湾国语 / 粤语挑设备上的系统语音（标出增强 / 高音质），选中后从当前段落用新语音接着读，并记住选择；选中的语音被删掉时退回自动；App 回到前台时重新读取语音列表，在系统设置里下载完切回来就能选。定时停止：不定时（默认）/ 读完本章 / 15 / 30 / 60 分钟，到点后读完当前这一段再停；面板上只显示选了哪一档，不倒数剩余时间；每次听书重新开始都回到不定时。音频会话由 `expo-audio` 设为 playback 并开启 `UIBackgroundModes: audio`，静音键打开、锁屏或切到后台都能接着读；全书读完、手动换章或离开阅读页即停。锁屏和控制中心显示「正在播放」（章节名、书名、cover.png），锁屏的播放 / 暂停、上一首 / 下一首和耳机线控、AirPods 都能用：上一首 / 下一首按段落跳，本章最后一段再往后跳到下一章开头；不给时长，锁屏不显示进度条。来电等打断时暂停，打断结束后接着读；耳机拔出时暂停，不改用扬声器外放。这部分由本地原生模块 `apps/mobile/modules/now-playing`（MPNowPlayingInfoCenter + MPRemoteCommandCenter）完成，改了要重新 `pnpm mobile ios`。自动时选设备上音质最好的普通话语音（高音质 > 增强 > 默认，前两种在 设置 → 辅助功能 → 朗读内容 → 声音 里下载；expo-speech 把 premium 也报成 Default，音质从 identifier 判断）
- 阅读器网页（`packages/reader/`）用 esbuild 打成单个 HTML（JS、CSS、KaTeX 字体全部内联，带禁止网络请求的 CSP），作为资源文件随 App 发布；启动时拷到 `documentDirectory/reader/`，WebView 以 `file://` 加载并获得整个 `documentDirectory` 的读权限，书里的相对路径图片因此可以直接显示
- 示例书在构建时由 `apps/mobile/scripts/build-samples.mjs` 生成成 TS 模块，首次启动时写入 `books/`，删除后不会再出现

### 8.1 预生成录音（方案，未实现）

听书的扩展：在电脑上用云端 TTS（目前是 Fish Audio S2.1 Pro）预先把书读成音频，随书推到手机，听感接近真人朗读。**体验与系统语音听书完全一致**：同样按段落高亮、跟随、跳段，同样的播放面板、定时、锁屏和耳机控制，只是声音来自录音文件。没有录音或录音过期的章节照常用系统语音，录音只是可选的附件。App 仍然不联网，联网生成只发生在电脑上的 `shelf-pack`。

**核心思路：按阅读器的段落录音，一段一个文件**

听书本来就是一段一段读的（`ttsBlocks` 切出的段落），录音按完全相同的段落生成，播放时「读第 i 段」就是「播第 i 段的文件」，高亮、跳段、进度不需要任何时间戳。

- 切段只有一份实现（已完成）：markdown-it 配置在 `packages/reader/src/render.ts`，切段规则在 `segment.ts`，两者都不依赖页面状态。`shelf-pack` 的 `src/segment.ts` 在 happy-dom 里跑同一份代码，得到与手机上完全相同的段落文字；`segment.test.ts` 默认对 `apps/mobile/samples/` 的示例书、设了 `SHELF_LIBRARY` 时对整个书库里每本能通过 check 的书分别走阅读器（`collectBlocks`）和 CLI 两条路径，段落必须逐条相同。happy-dom 每章新开一个窗口、用完关掉，关掉的窗口要等事件循环空闲才释放，整库连续同步切会耗尽内存
- 指纹用 `@shelf/spec` 的 `textHash`（与内容指纹同一套 64 位 FNV-1a，App 和 CLI 都能算，不依赖 Node 的 crypto）：段落的 key 是 `textHash(段落文字)`，只看文字；录音文件名是 `textHash(合成用文字 + 音色 + 参数)`，如 `3f2a9c…（16 位）.mp3`。超过单次上限（免费版 500 字符，CLI 按 450 切）的段落按句切成多个文件，清单里记成一个数组，顺序播放
- S2 会把方括号当成语气标签（如 `[whisper]`），合成时正文里的 `[` `]` 换成全角 `【` `】`；段落 key 仍按原文算
- 「此处有代码，略过。」这类重复的提示只生成一次，指纹相同自然复用

**音频包**

```text
books/<分组>/<书名>/audio/  # 书库里和 assets/ 并列，mp3 走 Git LFS；打包推书时不带
├── manifest.json           # { version: 1, bookId, voice: { provider, id, name }, params, chapters: { "<章节文件>": [{ key, files: [指纹…] }, …] } }
└── <指纹>.mp3              # 64 kbps 单声道；deepseek-harness 4.2 万字（按段落去掉代码、表格后）约 1.8 小时
```

- 放在书库里书的目录下：改书名、换分类时跟着书走；音频体积是原文的几百倍，`pack` 跳过 `audio/`（`isLibraryOnly()`），不随书打包，另走按章的音频包推送。mp3 用 Git LFS 管理（GitHub 免费 10 GB 存储，全库约 4 GB），清单 `manifest.json` 仍是普通文本。清单只按章节文件名和段落指纹对应，书库改目录、改章节文件名时改写清单即可，录音不用重新生成
- 清单的 schema 和匹配函数 `chapterAudio()` 在 `@shelf/spec` 的 `audio.ts`：本章段落数相同、每段 key 都逐条相同才返回各段的录音文件
- 清单只收录音全部齐全的章节；中断（Ctrl-C）时也先写清单，App 不会拿到缺文件的章
- 增量生成：修订书后重新运行，只有文字变了的段落指纹会变，只补生成这些段落；清单里不再引用的文件清理掉
- 换音色或参数后所有指纹都变，等于整本重新生成

**传到手机**

- 按章分包推送（`<id>.audio.<章节>.zip`，每包 5–10 MB），不放宽第 5.2 节的 50 MB 上限：fflate 整包读进内存，一次 65 MB 以上在手机上不划算
- 音频包同样走第 6 节的导入管线：`isAudioPackage()` 看 zip 根目录有 `manifest.json`、没有 `book.yaml` 和 `.md`，就交给 `prepareAudioImport()`（只放行 `manifest.json` 和 `<指纹>.mp3`，路径不安全、多出别的文件或缺录音都拒绝）。AirDrop、「文件」、局域网上传都能导入。写到 `documentDirectory/audio/<id>/`，**不放进 `books/<id>/`**：书更新时整目录原子替换，放在里面会被一起冲掉
- 书必须已经在书架上，否则提示先导入书。先写录音、最后写合并后的清单（`mergeAudioManifest()`：音色和参数相同按章覆盖，换了就整份替换），再删掉清单不再引用的录音
- `push-audio` 先查 `/books` 确认手机上有这本书，再用 `GET /audio/<id>` 取手机上的清单，`sameChapterAudio()` 相同的章跳过；每章一个包，不压缩（mp3 本来就压缩过），和其他章共用的提示语录音每个包各带一份
- 书更新后不必重推录音：指纹对得上的段落继续可用。删除书时一并删除录音；「书籍管理」页的占用空间把录音算进去，有原声的书标出「原声 xx MB」；书籍详情「···」里的「删除本书原声」先确认再删
- `@shelf/spec` 的扩展名白名单不变（书包里仍然不允许 `.mp3`），音频包有自己的白名单，同样写在 `@shelf/spec`

**播放**

- 播放引擎接口在 `apps/mobile/src/reader/engines.ts`（排一段、暂停、继续、停止、段落开始 / 结束回调）：系统语音一份（`expo-speech`），原声一份（`expo-audio` 的 `AudioPlaylist`）；队列、换章、定时、跳段、锁屏控制仍在 `speech.ts` 里只写一次
- 原声把所有段落的录音排进同一个 `AudioPlaylist`（底层是 AVQueuePlayer），段与段、同为原声的章与章之间无缝衔接；下一章换了引擎时两边队列不相通，等本章最后一段读完再开始下一章
- 录音放在 `documentDirectory/audio/<id>/`（`audioDir()`），开始读一章时用 `chapterAudio()` 对段落，并确认文件都在
- **以章为单位选引擎**：开始读一章时，本章每一段的指纹都能在清单里找到才用录音，否则这一章整章用系统语音，不在一章中间换声音。面板上的语音名显示实际在用的那一个
- 后台时没有声音的间隙里 App 可能被挂起：同一个播放列表内不会有间隙，原声 ↔ 系统语音换章的那一下要在真机锁屏下验证
- 语速沿用 0.8 / 1 / 1.25 / 1.5 档，原声直接改 `playbackRate`，不从段首重读（AVPlayerItem 默认保持音调变速）
- 锁屏和控制中心仍由 `apps/mobile/modules/now-playing` 负责；`expo-audio` 播放器不开启它自己的锁屏控制（`setActiveForLockScreen`），要先确认两者不会互相覆盖「正在播放」信息
- 界面上统一叫「原声」，不显示音色名：一套书库只用一个固定音色，用户只需要知道这一章能不能用原声
- 「朗读语音」面板：本书有原声时在「自动」下面多一项「原声」，副标题只写本章是否支持（「本章支持」/「本章暂不支持」）；「自动」在本章支持原声时优先用原声，否则用音质最好的普通话语音
- 播放面板只有右下角的语音按钮不同：用原声时显示波形图标和「原声」；本章不支持、退回系统语音时，标题下方多一行提示「本章暂不支持原声，先用系统语音读」，不弹窗、不打断
- 书籍详情「···」菜单多一项「删除本书原声」（显示占用空间，书和笔记都保留）；「书籍管理」里有原声的书标出「原声 xx MB」，占用空间算进书和分组的合计
- 设计稿：`design/设计稿.pen` 的「v11 · 阅读 · 选择语音 · 原声」「v11 · 阅读 · 听书 · 原声」「v11 · 阅读 · 听书 · 本章不支持原声」「v11 · 书籍详情 · 更多 · 有原声」「v12 · 书籍管理 · 含原声」

**CLI**

```bash
shelf-pack audio <book> [--voice <id>] [--speed 1] [--only 01,02] [-j 3] [--dry]   # 生成或增量更新书目录下的 audio/
```

- 密钥从钥匙串读取（`security find-generic-password -s fish-audio -w`），也可用环境变量 `FISH_API_KEY`，不进仓库
- 调用 `POST https://api.fish.audio/v1/tts`，请求头 `model: s2.1-pro-free`，`format: mp3`、`mp3_bitrate: 64`，固定 `reference_id`（音色）；默认 3 路并发，429 / 5xx 退避重试，已生成的文件跳过，可以随时中断再续
- 默认音色 `e0cbb35d7cc2420c87f2ea6ad623b61a`（「成熟男性讲故事」）；生成前打印段落数、字数、预计时长和本次要合成的数量；`--only` 只生成指定章节（文件名或序号前缀）；`--dry` 按段落输出朗读稿，方便检查读法
- 合成先写 `.part` 再改名，中断后留下的都是完整文件；密钥无效这类不可重试的错误立刻停下，其余失败列出来，重跑同一命令补上

**验证顺序**（每一步都能单独停下）

1. 切段抽成 `render.ts` / `segment.ts`，CLI 与阅读器段落一致的测试通过（已完成）
2. `shelf-pack audio` 生成一本书（先用 `deepseek-harness`），在电脑上抽听（命令已完成）
3. App 播放引擎接口 + 录音引擎，先只支持前台播放，确认高亮、跳段、语速（已完成，模拟器里验证了高亮跟随、跳段、暂停、切换语音、本章不支持时退回系统语音，以及系统语音章 → 原声章的自动换章）
4. 真机验证锁屏、后台连续播放、耳机线控、来电打断，以及与 `now-playing` 模块的共存
5. 音频包导入与按章推送（已完成，推送现在由 Dock 完成；模拟器里验证了从「文件」导入两章、合并清单、书籍管理的原声标签和删除本书原声。Dock 推送原声已在模拟器上实测）

**未决问题**

- Fish 免费模型的期限：官方 changelog 写明 `s2.1-pro-free` 免费到 2026-11-30，之后的价格未公布；全库约 386 万字、160 小时以上，只给常听的书生成
- 逐段单独请求时，段与段之间音色可能有细微漂移（跨请求不能参考上一段音频），需要整章试听确认；必要时降低 `temperature`
- 多音字、英文缩写（如 DSH、MCP）的读法：Fish 支持发音词典（`pronunciation_dictionary`），需要时在 `manifest.json` 旁维护一份
- 段落很短（标题、列表项）时请求数会明显增多，一本书大约几百到上千次请求，要看免费额度的频率限制

## 10. shelf-pack CLI 与 Dock

```bash
shelf-pack new   <分类> <书名>                # 新建一本书：生成 UUID，建好 books/<分组>/<书名>/、book.yaml 和第一章
shelf-pack mv    <book> [--title t] [--category c]   # 改书名或分类：移动目录，改写书库里指向它的链接和 next
shelf-pack check [target]                     # 按 spec 校验；不传就是整个书库
shelf-pack ls    [target]                     # 按 category 分组列出书名、章数、更新日期、有无原声
shelf-pack audio <book> [--only 01,02] [--dry]  # 生成原声录音到书目录下的 audio/（见 8.1）
```

shelf-pack 只管写书：新建、改名、校验、列出、生成原声，给 agent 用。推书、拉笔记、备份都在 Dock 的网页里做（见 5.2）。理想流程：agent 写完一本书并 `check` 通过 → 在 Dock 里勾选、推送 → 手机上确认后直接可读。

命令行和 Dock 共用 `@shelf/library`（`packages/library`）：找书、读书、校验、打包、原声包都在这里，`cli.ts` 只是一层命令行外壳。

在本仓库根目录以 `pnpm shelf-pack <命令>` 运行。书库默认是本仓库旁边的 `../hatch-shelf-library`，与当前目录无关；环境变量 `SHELF_LIBRARY`（相对本仓库根目录）可以指到别处。书库是纯数据仓库，里面没有 `package.json`，在书库里工作时用 `pnpm --dir ../hatch-shelf shelf-pack …`。

- `<book>` 写书名、书名的一部分（不分大小写）、`分组/书名`、id 或目录都可以（`findBook()`），部分匹配到多本时报错并列出来；`<target>` 还可以是书库里的分组名或任意目录，递归找出里面的书（`resolveTarget()`）。本仓库自己只剩 `apps/mobile/samples/` 两本示例书，`check apps/mobile/samples` 校验它们

- `check` 比 App 导入更严格：导入时会被跳过或兜底的情况（缺少 `book.yaml`、缺失章节、未列入 `chapters` 的 `.md`）在这里都会报出来；另外检查每章唯一 H1、代码块语言、远程图片、图片是否存在于 `assets/` 下，以及链接指向的章节、小节是否存在。书库里的书（上层有名为 `books` 的目录）还要满足书库约定：目录等于 `<分组>/<书名>`、id 是 UUID、跨书链接和 `next` 按路径写并指向书库里存在的书；书库外的书（示例书、单独拷出来的书）按手机写法 `../<id>/` 在同级目录里找，找不到时跳过。规则在 `@shelf/spec` 的 `lintBook()` / `lintLinks()`
- `packBook()` 打出的 zip 把文件放在 `<id>/` 下，只包含允许的扩展名，不带 `audio/` 和 `notes.md`；书库里的跨书链接和 `next` 换成 id 写法
- 「有更新」比较内容指纹：`@shelf/spec` 的 `prepareImport()` 对将要写入设备的全部文件算出 `hash`，App 导入时存到书目录下的 `.content-hash` 并进入索引，`/books` 返回它；Dock 用同一个函数解开自己打的 zip 得到指纹，相同即已同步。设备上没有指纹的书（早期导入的、示例书）总当作有更新
- 拉笔记和推书方向相反：可以先拉笔记、让 agent 据此修订书，再推送有变化的书。和本地文件只差导出日期时不重写，避免每次拉取都产生 diff；手机上已没有高亮的书不会删除本地笔记文件

## 12. 决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 内容分发 | 不做热更新，纯单机 + AirDrop / 局域网 | OTA 会把内容与 runtimeVersion 绑死，只能全量下发，EAS 在国内连通性差；单机方案零后端 |
| 渲染方式 | WebView 而非 RN 原生 Markdown 组件 | 原生组件对代码高亮、公式、Mermaid、宽表格的支持弱 |
| 仓库 | 代码仓库 `hatch-shelf`（公开）+ 书库 `hatch-shelf-library`（私有、纯数据），两者放在同一父目录；shelf-pack 留在本仓库，默认找旁边的书库，不发布 npm 包 | 起初单仓库够用；书写到近百本、又有了 4 GB 原声后，内容提交过半、历史里内容占九成，录音没处备份。书库独立后可以私有、用 LFS 管录音、单独给写书的 agent 一套规范。示例书随安装包发布，算代码，留在 `apps/mobile/samples/`；shelf-pack 的每个部分都在和 App 对接（导入格式、阅读器切段、局域网接口、链接写法），放在本仓库才能和 App、spec 一起改、一起测；书库里不放 package.json，只有数据和写书规范。spec 改动偶尔要两边各提交一次，可以接受 |
| 目录结构 | 应用放 `apps/`（`mobile`，之后加电脑端 `dock`），共用代码放 `packages/`（`spec`、`reader`、`library`）；原来的 `app/`、`app/reader-web/`、`tools/shelf-pack/` 按此搬家，Bundle ID、显示名和 `expo.name` 不变 | 要加一个电脑端应用后，`app/` 这个名字分不清是哪一端，阅读器网页挂在 App 目录下、CLI 单独放在 `tools/` 也说明不了它们是共用的包。按「应用 / 共用包」两层分开，书库逻辑抽成 `@shelf/library` 后，电脑端和写书命令都能直接调用 |
| 书库目录 | `books/<分组>/<书名>/`（分组是 category 第一段），章节文件用中文名，id 用 UUID，原声和笔记放进书目录；跨书链接和 next 在书库里按路径写，打包时翻译成 id | 近百本书平铺成英文 id 不便浏览，起语义化 id 也要花心思、改书名后还会名不副实。人只看目录和中文文件名，UUID 只给机器用；跨书引用按路径写，在编辑器里能点通，改书名用 `shelf-pack mv` 一并改写。子分类大多只有一两本书，不建目录。迁移时手机上的旧数据不保留，重新推书 |
| 数据源 | 文件即真相，SQLite 只做索引 | 索引可重建；以后加任何同步通道，阅读器都不用改 |
| 局域网方向 | 手机做服务端，电脑做客户端 | App 不主动发起网络请求；电脑一侧（现在是 Dock）找到手机后推送 |
| 阅读器加载方式 | 单文件 HTML 资源 → 拷到 documentDirectory → `file://` 加载 | 用 `source={{ html }}` 时页面拿不到本地文件读权限，图片只能转 base64；放在 documentDirectory 下与 books/ 同源最简单 |
| Markdown 在哪渲染 | WebView 内（RN 只传原文） | 渲染库只打包一份；RN 侧不需要 DOM 环境 |
| 宽图表 | 竖屏下自动转向 + 缩到屏幕宽 + 点按全屏看原图，不做横屏 | App 锁定竖屏；横向滚动看不到全貌，转成上下方向后多数流程图正好放得下，其余缩小看全貌、点开看细节 |
| 书中配图 | Mermaid + SVG，不用字符画 | 字符画在手机窄屏上会错位、看不清；SVG 是文本、体积小、矢量可放大，能进 git diff。SVG 自带白底，因为 `<img>` 里拿不到阅读器主题变量 |
| push --changed 的依据 | 内容指纹而非 `updated` | 改了内容忘记改日期时会漏推；指纹由 App 与 CLI 共用的 `prepareImport()` 计算，两边必然一致 |
| 高亮定位 | 原文 + 前后文，而非字符偏移或 DOM 路径 | 书会被 AI 反复修订；偏移和 DOM 路径一改就失效，原文 + 前后文在小改动后仍能找回 |
| 搜索分词 | FTS5 trigram，短查询退回 LIKE | 不需要中文分词词典；trigram 要求至少 3 个字符，个人书库规模下 LIKE 扫描足够快 |
| 阅读主题 | 跟随 App 外观，去掉护眼主题 | 设计稿要求阅读页与整个 App 一致；外观集中在设置页切换，阅读设置只留字号、行距和代码换行 |
| 推书入口 | 电脑上用 Dock 网页（本地 Node 服务 + 浏览器），去掉 shelf-pack 的 push / pull-notes / backup / restore / pack / push-audio 和手机自带的上传网页；手机上去掉「传书」Tab，改为书架「+」进入的接收模式 | 原来每次都要在手机上开传书、抄 IP 和 4 位 PIN，再把它们填进每一条命令；一次完整同步要跑好几条命令，还看不出书库和手机差在哪。Dock 读本地书库、和手机逐本比对，状态一目了然、勾选即推；传书一年用不了几次，不值得占一个 Tab。写书的命令（new / mv / check / ls / audio）留给 agent |
| 配对 | Dock 生成密钥做成二维码，手机扫码后长期保存，取代每次重新生成的 PIN；Dock 扫描 /24 网段找手机，不用 Bonjour | 扫一次永久有效，不用再输入任何东西；4 位 PIN 能被枚举，所以以前要锁定计数，128 位密钥不需要。扫网段不新增原生依赖，家用网络一次不到 4 秒 |
| 推送确认 | Dock 每次推送都要先在手机上点「开始接收」，接收结束后自动关闭服务（推送完 8 秒、空闲 5 分钟） | 手机上能看到要来什么、可以拒绝；服务不再需要手动停止，也不会忘了关 |
| Dock 的存储 | 书库路径、配对密钥、手机地址都存在浏览器 localStorage，书库路径没有默认值 | 服务端保持无状态，换个浏览器就是一套新设置；只监听 127.0.0.1 并校验 Host / Origin |
| 动效实现 | RN Animated，不引入 Reanimated | 设计稿的动效都是淡入、位移、弹簧这类简单动画，Animated 的原生驱动足够；少一个原生依赖 |
| 解压库 | fflate 而非 react-native-zip-archive | 纯 JS，少一个原生依赖；解压前就能逐条检查路径与大小；App 与 CLI 共用同一份导入逻辑，并能在 Node 里测试。50 MB 上限内整包读入内存可以接受 |
| 发布方式 | 本地 xcodebuild archive 后直接上传 TestFlight，不用 EAS Build / Submit | EAS 在国内连通性差；签名交给 Xcode 自动管理，`ios/` 仍然只由 prebuild 生成 |
| 版本号与构建号 | 只维护 `expo.version`，每次上传升 patch，构建号不设、用 Expo 默认的 1 | 苹果只要求同一版本下构建号不重复，每次都升版本，构建号恒为 1 就够；两个号分开递增容易忘。早先让构建号取与 version 相同的值，没有必要，改回默认。个人自用不需要同一版本多次上传，一次一版最简单 |
| 书架分组 | 分组名就是 `category` 的第一段，直接写中文；顺序按系列里最早导入的书 | 分组名写死在 App 里时，新增系列要改代码、重新出包，违背「内容跟着书走」；导入时间在重建索引时保留，顺序稳定，不需要额外配置 |
| 阅读数据备份 | 手动导出 JSON + 合并式恢复，不做自动同步 | App 不联网，iCloud 同步要引入原生能力和冲突处理；进度和高亮都带 `updated_at`，按「较新者胜」合并足够个人使用。备份是个人数据，`backups/` 不入库 |
| 跨书链接 | 手机上用文件系统式的相对路径 `../<id>/<章节>.md#锚点`，不用自定义 scheme；书库里写 `../../<分组>/<书名>/<章节>.md#锚点`，打包时换成前者 | 与 App 里 `books/<id>/` 的目录结构一致，阅读器按相对路径就能解析；书库里的写法则与书库的真实目录一致，在 GitHub 和编辑器里能点通 |
| App 名称 | 显示名「书巢」，内部名保留 `Shelf` | 取陆游《书巢记》里堆满书的书房，也呼应 hatch（孵化）：书在电脑上写成，再落进手机里的巢。「书架」仍作为首页 Tab 的名字；`expo.name` 决定 prebuild 的工程名和 TestFlight 脚本的 scheme，不随之改动 |
| 冷启动 | 不全量重建索引，开场封面只播一次 | 每次启动都读遍全部章节重建全文索引，书越多开屏越久；索引存在 SQLite 里，导入时已按书更新，冷启动只做不读正文的增删对账，结构变化时靠 `INDEX_VERSION` 触发一次全量重建。开场封面每次都播会让「打开就读」变慢 |
| 阅读页换章 | 去掉底部上一章 / 下一章，换章只走目录；目录、本书笔记、阅读设置收进「···」菜单 | 底部导航常驻会挡住正文，阅读时几乎只在读完一章时用一次；顶部三颗按钮也让阅读页显得像工具页。只留返回和「···」，正文铺满全屏 |
| 读完推荐 | 推荐写在 `book.yaml` 的 `next`，App 只负责显示；不按阅读记录自动推荐 | 阅读路线本来就由导读书维护，写在内容里改起来只需推书；按记录推荐需要额外的数据和规则，结果也不如人写的路线可解释。卡片只放书名和一句理由，不放进度、时长之类的统计 |
| 听书 | 系统语音 expo-speech，音频会话设为 playback；读完一章自动接下一章，锁屏「正在播放」和远程控制用本地原生模块 | 系统语音完全在本机、不收费，符合 App 不联网；默认音频会话下静音键会让朗读没声音、锁屏就停，设成 playback 只多一个 expo-audio。后台时 WebView 被冻结，所以开始听书时就把后面各章一起切好段落，换章不依赖 WebView。锁屏控制最初觉得不值得自写原生代码，但跑步等不看屏幕的场景离不开耳机和锁屏按钮，本地模块只有一个 Swift 文件；expo-audio 的锁屏控制绑定在它自己的播放器上，接不到 AVSpeechSynthesizer |
| 开发版包名 | 默认构建 `com.jarvis.shelf.dev`，只有 TestFlight 脚本用正式包名 | 真机调试时不覆盖正式版和里面的书、笔记；默认值选开发版，忘了设环境变量时最坏只是多装一个开发版 |
| 进书过场 | 按正文版式画静止的占位，渲染完成后原地淡出，不用加载指示 | 转圈和闪白会打断「页面本来就在那里」的感觉；占位与真正文对齐，显影时只有淡墨行化成文字 |
| 点按与长按书籍 | 点按直接进阅读页，长按进书籍详情；长按预览与详情页合并为一页，以封面为主 | 打开书最常见的目的就是接着读，先经过详情页选章节多了一步；长按预览和详情页内容大半重复。封面都是精心画的原稿，详情页让它占首屏一半以上，目录改成封面下方的横滑章节卡，不用上滑就能看到 |
| 批量删除入口 | 设置页单独的「书籍管理」页，不在书架上做多选模式 | 书架以封面为主，长按已经用于进详情；在书架上叠一层勾选态会和长按、封面飞行冲突。批量删除是低频的整理动作，放在设置里一页列表最清楚，还能顺带展示每本书和各系列占用的空间 |
| 书架下拉刷新 | 去掉，手改书内文件后到设置页「重建索引」 | 书都经导入管线进来，索引当场更新，只有绕过管线直接改文件才需要全量扫描；下拉刷新会让人以为在联网拉新内容，单机书架拉了也没有变化，而全量重建又重又容易误触。设置页本来就有同样的入口 |
| 预生成录音（方案，见 8.1） | 电脑上用云端 TTS 按阅读器的段落逐段录音，随书推到手机；按章选用录音或系统语音；录音存在 `documentDirectory/audio/<id>/`，不进 `books/` 和仓库 | 系统语音的听感明显不如大模型 TTS，但 App 不能联网，只能在电脑上生成好再传过去。按段落而不是按章录音，现有的段落高亮、跳段、进度都能原样沿用，不需要时间戳（Fish 的 TTS 接口也不返回时间戳）。文件名用段落文字的指纹，书修订后只需补录改过的段落，对不上的章节退回系统语音，不会读错位。一章内不混用两种声音，免得中途换人。音频体积是原文的几百倍，放在书目录里会被书更新时的原子替换冲掉，进仓库则让公开仓库背上大量二进制；按章分包推送，不必放宽 50 MB 的导入上限 |

## 13. 发布到 TestFlight

开发版和正式版分开：`apps/mobile/app.config.js` 默认生成开发版（Bundle ID `com.jarvis.shelf.dev`、桌面名「书巢 Dev」、URL scheme `shelf-dev`），和 TestFlight 装的正式版在同一台手机上并存，各有各的书和数据；只有 `pnpm mobile testflight` 设 `APP_VARIANT=production`，用 `app.json` 里的正式值。`expo run:ios` 在 `ios/` 已存在时不会重新生成工程，所以 `pnpm mobile ios` 先跑一次 `expo prebuild`，把 `ios/` 切回开发版，打完 TestFlight 再装开发版也不会覆盖正式版。

一次性准备：在 App Store Connect 用 Bundle ID `com.jarvis.shelf` 建好 App；Xcode 的 Settings → Accounts 登录开发者账号（脚本用它签名和上传）。

```bash
pnpm mobile testflight                  # 版本号升 patch → build:assets → prebuild → archive → 上传 → 提交、打 tag 并推送
pnpm mobile testflight --version 1.1.0  # 指定新版本号（升 minor / major 时用）
pnpm mobile testflight --no-upload      # 只导出 .ipa 到 apps/mobile/ios/build/export，不改版本号
```

- 只维护 `app.json` 的 `expo.version` 一个号：每次上传都是新版本，脚本自动升 patch（或用 `--version` 指定），失败时恢复原值；上传成功后脚本自动单独提交 `app.json`（`chore(release): v<版本>`）并打同名 tag `v<版本>`，不带上工作区的其他改动，再用 `git push --follow-tags` 把这个提交和 tag 推到远端（当前分支需要已设上游；推送失败时提交和 tag 留在本地，按提示手动推）；`git log --oneline --decorate` 或 `git tag` 即可看到各版本节点
- 构建号（`CFBundleVersion`）不设，用 Expo 默认的 1，不要在 `app.json` 或 `app.config.js` 里写 `ios.buildNumber`。同一版本只能上传一次，上传后处理失败也要升版本重传
- 上传后 App Store Connect 处理 5～15 分钟，构建出现在 TestFlight 的内部测试组即可安装；内部测试不需要审核，构建 90 天后过期

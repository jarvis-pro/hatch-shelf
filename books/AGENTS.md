# 写书规范

本目录下的每个子目录是一本书。任何 agent 在这里写书时必须遵守本文件；完整背景见仓库根目录 `README.md` 第 4 节。

要写哪些书、每本的大纲和进度见 `ROADMAP.md`；写完一本按其中「约定」更新进度。

## 目录结构

```
books/<book-id>/
├── book.yaml
├── cover.png          # 可选；缺省时 App 自动生成文字封面
├── 01-xxx.md
├── 02-xxx.md
└── assets/            # 本书的全部图片
```

## book.yaml

```yaml
id: go-concurrency            # 必填，全局唯一，[a-z0-9-]，必须与目录名一致；同 id 再次导入即为更新
title: Go 并发编程实战          # 必填
subtitle: 从 goroutine 到调度器  # 可选
category: 技术/Go             # 可选，书架分组，用 / 分层
tags: [go, concurrency]       # 可选
level: intermediate           # 可选：beginner | intermediate | advanced
created: 2026-11-02           # 可选，YYYY-MM-DD
updated: 2026-11-02           # 可选，每次修改内容时更新（只用于展示，是否推送按内容判断）
chapters:                     # 必填，显式排序；未列入的 .md 会被忽略
  - 01-goroutine.md
  - 02-channel.md
```

`category` 的第一段就是书架上显示的分组名，直接写中文（如 `人工智能/Agent`、`自媒体/平台`），同一系列的书第一段要一字不差；App 不做映射，新系列推书即生效。

字段的权威定义是 `packages/spec/src/schema.ts`，两者冲突时以代码为准并修正本文件。

## 硬规则

- 每章一个 `.md` 文件，以**唯一**的 H1 作为章标题；章内用 H2 / H3 组织（阅读器目录取 H1–H3）
- 文件名只使用 `[a-z0-9-]` 和 `.md`，建议用两位序号前缀：`01-intro.md`
- 图片放在本书 `assets/` 下，用相对路径引用：`![说明](assets/xxx.png)`
- **禁止远程图片**（`http(s)://`），手机离线时无法显示
- 图表用 Mermaid 或 SVG，**禁止用字符画图**，详见下方「配图」
- 代码块必须标注语言（` ```go `、` ```bash `、` ```text ` …）
- 数学公式使用 KaTeX 语法：行内 `$...$`，块级 `$$...$$`
- 图片格式限于 png / jpg / jpeg / gif / webp / svg，其余文件导入时会被丢弃
- 提到本书其他章节或另一本书时写成链接，阅读器点按即可跳过去（跨书时返回会回到原处）：
  - 本章小节：`[说明](#小节标题锚点)`
  - 本书其他章节：`[第 3 章](03-xxx.md)`、`[某小节](03-xxx.md#锚点)`
  - 另一本书：`[《RAG 系统》](../rag-systems/)`（打开到上次读到的位置）、`[检索评估](../rag-systems/05-eval.md#锚点)`
  - 锚点是标题文字转小写、空格换成 `-`、去掉标点后的结果（如 `## Stream 与背压` → `stream-与背压`），同一章重名标题依次加 `-1`、`-2`
  - `check` 会校验链接的书、章节、小节是否存在；其他写法（如 `assets/x.svg`、`../../`）会报错
- **法规、财税、版本敏感的内容**（税率、申报期限、政策条款、平台规则、软件版本行为等凭记忆写的内容）必须加 `> [!WARNING]` 提示块，写明「以官方最新规定为准」和应去核对的官方来源，放在该内容所在小节的开头：

  ```markdown
  > [!WARNING]
  > 本节税率和起征点按 2025 年的规定整理，可能已调整，以国家税务总局最新公告为准。
  ```

- 其他提示块按需使用，阅读器会渲染成带图标和标题的彩色卡片：`> [!NOTE]`（注意，补充说明）、`> [!TIP]`（提示，技巧）、`> [!IMPORTANT]`（重要，不能漏看的要点）、`> [!CAUTION]`（当心，操作有风险）。标记独占引用块第一行，大写；一章里不要堆太多，普通的补充用普通引用块 `>` 即可

## 配图

### 选哪种形式

| 要表达的内容 | 用什么 |
|---|---|
| 流程、步骤、结构、层级、时序、状态变化 | Mermaid（` ```mermaid `），写法见下方「Mermaid 怎么写才适合竖屏」 |
| 柱状图、折线图、坐标图、网格 / 矩阵示意、带标注的示意图 | SVG，放在 `assets/` |
| 按行列组织的文字和数字 | Markdown 表格 |
| 原样的文本：prompt、命令输出、日志、对话示例 | ` ```text ` 代码块 |

**禁止在代码块里用字符拼图**：`│ ╲ └─` 画坐标轴和曲线、`████` 画柱子、空格对齐的 ✓ 矩阵、ASCII 方框图等。它们在手机窄屏上会错位、换行，也看不清。代码块只放「本来就是文本」的内容。

### Mermaid 怎么写才适合竖屏

阅读器在竖屏手机上，正文宽约 343pt。为了在这个宽度下看清：

- 流程图默认用 `flowchart TD`（上下方向）；只有 3 个以内节点的短链才用 `LR`。阅读器会把过宽的 `LR` 自动转成 `TD`，但源文件里直接写对更可控
- 节点文字短一些：每行不超过 8 个汉字，需要说明的放在正文里，用 `<br/>` 分行而不是写长句
- 时序图的参与者不超过 4 个，名字用简称；参与者多的拆成两张图
- 同一层并排的节点不超过 3 个；分支多时用子图（`subgraph`）分组，或拆图
- 阅读器会把仍然过宽的图缩到屏幕宽并提示「点按查看大图」，这只是兜底，不要依赖它

### SVG 规范

- **底板**：最外层一个白色圆角矩形（`fill="#ffffff"`、`stroke="#d8dee4"`、`rx="10"`）。阅读器有暗色主题，`<img>` 里的 SVG 拿不到页面的 CSS 变量，透明底在暗色下会看不清
- **尺寸**：`viewBox` 宽 360 左右，同时写上相同的 `width` / `height`；高度按内容定。手机正文宽约 343pt，这个宽度基本不缩放
- **字体**：`font-family="-apple-system, 'PingFang SC', 'Hiragino Sans GB', 'Helvetica Neue', sans-serif"`；标题 15、加粗 600，正文和标签 12–14，不小于 11
- **配色**（与阅读器亮色主题一致）：

  | 用途 | 色值 |
  |---|---|
  | 主色（数据、强调） | `#2f6fdf` |
  | 主色浅底 | `#dbe7fb` |
  | 次要数据、「其余」、未激活 | `#e6e9ed` |
  | 正文文字 | `#1f2328` |
  | 次要文字、坐标轴 | `#656d76` |
  | 边框、网格线 | `#d8dee4` |

- **内容**：每张图带标题；数据图的数字要真实或按公式算出，不要随手编；需要图例时放在图内底部
- **自包含**：不引用外部字体、图片、脚本，不用 `<foreignObject>`
- **引用**：`![一句话说明图的内容](assets/xxx.svg)`，alt 写成完整的句子；文件名 `[a-z0-9-]`，按内容命名，如 `causal-mask.svg`
- **生成方式**：手写或用脚本生成都可以，脚本不要放进书目录
- **自检**：提交前渲染出来看一遍，确认没有文字重叠、溢出。macOS 上可以用 `qlmanage -t -s 800 -o <输出目录> <文件>.svg` 生成 PNG 预览（它会裁成正方形，高图需先把 viewBox 补成正方形再预览）

## 读者笔记

仓库根目录的 `notes/<book-id>.notes.md` 是从手机导出的阅读笔记（高亮的原文 + 读者的想法，按章节分组，
每条带章节文件名和小节锚点）。修订一本书前，如果存在对应的笔记文件，先读一遍：
读者标出的疑问、没讲清楚的地方、想要展开的点，是修订的优先事项。不要修改笔记文件本身。

文件最前面的「存疑」一节是读者认为**可能有错**的地方（每条带章节文件和小节锚点，说明可能为空），最先处理：
逐条对照可靠来源核实；确实有错就改正，核实不了就在正文里写明依据有限、以官方最新规定为准，
并在 `REVIEW.md` 记一条待复核。不要因为读者存疑就直接删掉内容。

# 拆解对标：方法与模板

刷对标账号和拆对标账号是两回事。刷的时候你会觉得「这条好看」「这个人讲得好」，但说不出好在哪；拆的时候你要把一条视频拆成可以记录、可以比较、可以迁移的字段，比如开头第一句说了什么、第几秒出现第一个画面切换、评论区里多少人在问同一个问题。

这一章给两张表：账号层拆解表和作品层拆解表，再讲怎么采样、怎么测量、怎么从表里提炼出你能用的规律。下一章用一个完整示例把这两张表填满。

## 拆解的两层

| 层 | 回答的问题 | 拆几次 |
|---|---|---|
| 账号层 | 这个账号整体是怎么运转的：给谁看、讲什么、多久更一次、怎么赚钱 | 每个对标拆一次，每季度更新 |
| 作品层 | 单条内容是怎么做出来的：选题、开头、结构、节奏、画面、评论区 | 每个对标拆 10–15 条 |

只拆作品不拆账号，你会学到很多技巧但不知道它们为什么有效；只拆账号不拆作品，你知道方向但做不出一条像样的内容。

## 采样：拆哪些条

不要只拆爆款。只看爆款，你会把运气当成规律。建议每个对标这样取样：

| 样本 | 数量 | 用途 |
|---|---|---|
| 最近发布的作品 | 5 条 | 看它现在的标准做法 |
| 历史数据最高的作品 | 5 条 | 看什么样的选题和结构能突破 |
| 同期数据明显偏低的作品 | 3 条 | 和高的对比，找差异 |
| 最早的作品（如果能看到） | 2 条 | 看它是怎么起步的、改过什么 |

「数据高低」看的是**相对它自己**：用点赞数或评论数和它最近 30 条的中位数比，明显高的算高、明显低的算低。不同账号之间粉丝量差距大，横向比绝对数字没有意义。

## 账号层拆解表

```text
【账号层拆解】  账号：______  平台：______  拆解日期：______  层级：头部 / 腰部 / 同起点

一、定位
  人群（从评论区推断）：____
  需求（最高赞几条在解决什么）：____
  形式：真人出镜 / 不出镜 / AI 画面；口播 / 录屏 / 剧情 / 图文
  人设句（替它写一句）：我是 ____，因为 ____，所以我只讲 ____

二、包装
  名字：____（结构：领域词 + 称呼？纯昵称？）
  头像：____（真人 / 卡通 / 文字 / logo）
  简介：____（原文抄下来）
  背景图：____
  置顶：____（置顶了哪几条，为什么是这几条）
  合集 / 栏目：____（名称和条数）

三、更新
  最近 30 天发布数：____
  固定栏目或系列：____
  单条时长分布：____（多数在几秒到几秒）

四、变现
  看得到的变现动作：橱窗 / 商品链接 / 广告合作标识 / 课程 / 简介里的联系入口 / 直播 / 无
  变现内容占比（最近 20 条里有几条带变现）：____

五、一句话总结
  它最值得学的一点：____
  我学不来的一点：____
```

## 作品层拆解表

这是本书最核心的一张表。每一列都有明确的记录方法，填的时候不要写感受，写事实：

| 列 | 记什么 | 怎么记 | 示例 |
|---|---|---|---|
| 编号 / 链接 | 方便回看 | 发布日期 + 序号 | 1018-03 |
| 数据 | 点赞、评论、收藏、转发 | 拆解当天的数字，并标「高 / 中 / 低」（相对该账号中位数） | 赞 1.2 万 / 评 860 / 藏 9000 / 转 2100，高 |
| 选题 | 这条讲什么 | 一句话，用观众的视角写 | 领导临时要汇总 30 个表，5 分钟搞定 |
| 选题类型 | 归类 | 痛点解决 / 清单 / 对比测评 / 避坑 / 故事 / 观点 / 热点 | 痛点解决 |
| 标题与封面字 | 原文 | 照抄，包括标点 | 「别再一个个复制了！」 |
| 开头 3 秒 | 第一句话 + 第一个画面 | 逐字照抄台词，描述画面 | 「领导让你汇总 30 个表？」画面：满屏 Excel 窗口 |
| 结构 | 时间轴分段 | 写成「0–3s 抛问题 / 3–12s 演示结果 / 12–40s 三步教程 / 40–45s 引导收藏」 | 见示例 |
| 节奏 | 时长、镜头切换数、语速 | 总秒数；数切换次数；台词字数 ÷ 分钟 | 45 秒；切 14 次；约 260 字/分钟 |
| 画面 | 出镜方式、景别、字幕样式 | 简短描述 | 录屏 + 局部放大；黄底黑字大字幕 |
| 结尾 / 行动引导 | 最后一句说了什么 | 照抄 | 「先收藏，下次领导找你就用得上」 |
| 评论区高频词 | 观众最常说什么 | 见下文「评论区怎么拆」 | 「WPS 能用吗」「Mac 呢」「求模板」 |
| 变现挂载 | 有没有商品、广告、引导 | 有就写是什么 | 无 |
| 我的判断 | 这条为什么高 / 低 | 一句话，必须基于前面的事实列 | 选题是高频痛点，开头直接复述领导的话，代入感强 |

把这张表放在电子表格里，每个对标一张工作表，同一个赛道的所有对标放在一个文件里，后面方便横向比。

## 怎么测量

### 逐字转写

开头 3 秒和结构这两列需要台词原文。方法：

1. 用语音转文字工具（剪辑软件自带的识别字幕、录音转写工具都可以）把视频台词转成文字
2. 对照视频改错字，标上每段开始的秒数
3. 只用于自己分析，**不要把别人的转写稿当成自己的文案发布**

### 计时和数镜头

- 节奏的核心指标是**镜头切换次数**和**语速**。用视频播放器逐段拖，或者把视频导入剪辑软件看时间线（只用于分析，不要用于二次发布）
- 语速：台词总字数 ÷ 视频时长（分钟）。例如 45 秒、195 字，语速 = $195 \div 0.75 = 260$ 字/分钟
- 平均镜头时长：视频时长 ÷ 切换次数。45 秒切 14 次，平均每个镜头约 3.2 秒

不需要精确到帧，精确到秒就够。你要找的是「这个账号普遍 2–3 秒切一次」这种量级上的规律。

### 评论区怎么拆

评论区是最被低估的数据源。它告诉你：观众是谁、他们没被满足的需求是什么、下一条该做什么。

每条拆解的作品，看按热度排序的前 50–100 条评论，按下面的类别计数：

| 类别 | 特征 | 用途 |
|---|---|---|
| 需求延伸 | 「那 XX 怎么办」「能不能讲讲 XX」 | 直接变成你的选题 |
| 适用性疑问 | 「WPS 能用吗」「手机可以吗」 | 你的内容可以提前覆盖，做出差异 |
| 求资源 | 「求模板」「求链接」 | 说明有变现空间（模板、工具、资料包） |
| 共鸣 | 「太真实了」「我领导也这样」 | 说明选题戳中了情绪，可以在开头放大 |
| 质疑 / 纠错 | 「这样不对」「有更简单的方法」 | 对标的漏洞，你的机会 |
| 无效 | 表情、「666」、无关内容 | 不计入 |

如果想统计高频词，可以把评论**手动复制**到一个文本文件里（一行一条），用一个小脚本数词。下面这个脚本只做本地文本统计，不访问任何网络：

```python
# count_comments.py —— 统计手动复制下来的评论高频词
# 用法：python3 count_comments.py comments.txt
# 依赖：pip install jieba
import sys
from collections import Counter

import jieba

STOP = set("的 了 是 我 你 他 她 也 都 就 吗 呢 啊 吧 这 那 有 在 和 一个 不 没 很 还 要 会 能 可以 怎么 什么".split())

def main(path: str) -> None:
    words: Counter[str] = Counter()
    with open(path, encoding="utf-8") as f:
        for line in f:
            for w in jieba.cut(line.strip()):
                w = w.strip()
                if len(w) >= 2 and w not in STOP:
                    words[w] += 1
    for w, n in words.most_common(30):
        print(f"{n:4d}  {w}")

if __name__ == "__main__":
    main(sys.argv[1])
```

```bash
python3 count_comments.py comments.txt
```

词频只是辅助。真正有用的是你读评论时对「这个人为什么这么说」的判断，脚本替代不了。

## 从表到规律

拆完一个对标的 15 条，你手上会有一张 15 行的表。接下来做三件事：

### 1. 对比高低

把「高」和「低」的作品放在一起，逐列看差异：

| 列 | 高的几条共同点 | 低的几条共同点 | 差异是不是原因？ |
|---|---|---|---|
| 选题类型 | | | |
| 开头 3 秒 | | | |
| 时长 | | | |
| 节奏 | | | |
| 画面 | | | |

最后一列要克制：15 条样本很少，一个差异只出现在两三条里，不能算规律。只记录**在多数高的作品里都出现、在多数低的作品里都没有**的特征。

### 2. 跨账号找共性

对 5 个腰部对标都做完后，把每个账号的「规律」放在一起：

```text
【跨账号规律汇总】  赛道：______  汇总日期：______

在 4–5 个对标里都出现的（大概率是赛道规律）：
  - ____
  - ____

只在 1–2 个对标里出现的（可能是个人风格）：
  - ____

所有对标都没做、评论区却有人要的（你的机会）：
  - ____
```

第三栏最重要。它通常来自评论区的「需求延伸」和「质疑 / 纠错」：对标们都在讲 Windows 上的 Excel，评论区一直有人问 Mac 和 WPS，这就是一个可以切进去的缝。

### 3. 区分可迁移和不可迁移

| 可迁移（可以学） | 不可迁移（学了也没用或不该学） |
|---|---|
| 选题类型和选题结构 | 具体的台词和文案 |
| 开头的写法（问题式、结果先行、反常识） | 博主本人的长相、口音、身份 |
| 段落结构和时长 | 对方的画面素材 |
| 节奏的量级（几秒一切） | 对方的品牌合作资源 |
| 字幕、封面的信息层级 | 依赖存量粉丝的随意内容 |
| 栏目设计和更新节奏 | 偶然蹭上的热点 |

## 拆完怎么用：结构仿写，不是内容复制

拆解的终点是写出**你自己的**内容。一个安全也有效的方法是「结构仿写」：保留对标的结构骨架，填入你自己的选题、经验和素材。

```text
【结构仿写对照】

对标原结构（时间轴）：
  0–3s   复述一个具体的职场场景（领导临时要数据）
  3–10s  直接展示做完的结果
  10–40s 三步操作
  40–45s 引导收藏

我的版本：
  0–3s   复述我自己的场景：____
  3–10s  展示我的结果：____（必须是我自己做出来的）
  10–40s 我的步骤：____（不同的工具 / 不同的方法 / 覆盖对标没覆盖的 Mac、WPS）
  40–45s 我的结尾：____

差异检查：
  - 选题和对标是否不同，或者在对标基础上解决了它没解决的问题？  是 / 否
  - 台词是否全部自己写？                                       是 / 否
  - 画面素材是否全部自己录？                                   是 / 否
```

三个都是「是」，才算你自己的内容。

### 洗稿和抄袭的边界

把别人的文案换几个词、把别人的视频重新剪一遍、把别人的口播稿换个人念，都是平台重点打击的「洗稿」「搬运」，也可能侵犯著作权。具体边界：

- **结构和方法不受保护**：「先抛问题再给答案」这类结构谁都能用
- **具体表达受保护**：台词原文、画面素材、配乐剪辑、独创的比喻和案例
- **事实不受保护，但对事实的独创性整理可能受保护**：一张别人精心整理的对比表，直接搬就有风险

拿不准的时候，问自己：如果对标博主刷到我这条，他会不会觉得「这是我的东西」？版权问题的系统讲法见[《自媒体与短剧合规财税》](../media-compliance/)。

## 拆解的节奏

| 阶段 | 拆多少 | 花多久 |
|---|---|---|
| 起号前 | 5 个腰部对标各拆 10–15 条 + 账号层；头部和同起点各拆 5 条 | 两个周末 |
| 冷启动期（前 30 条） | 每周从对标池新作品里挑 2–3 条高的拆 | 每周 1 小时 |
| 稳定期 | 每月拆一次，重点看对标的新尝试 | 每月 2 小时 |

起号前那两个周末不要省。你会发现，认真拆完 60 条以后，再看任何一条视频，脑子里会自动出现它的结构，这是写好自己内容的前提。

## 本章要点

- 拆解分账号层和作品层，前者看整体怎么运转，后者看单条怎么做出来
- 采样要包括最近、最高、偏低和最早的作品，「高低」相对对标自己的中位数判断
- 作品层拆解表的每一列都记事实：台词原文、时间轴、镜头切换数、语速、评论区分类计数
- 评论区按需求延伸、适用性疑问、求资源、共鸣、质疑分类；评论手动复制后可以用本地脚本数词频
- 规律只认在多数高作品里出现、多数低作品里没有的特征；跨账号都没做、评论区有人要的，就是你的机会
- 拆完用「结构仿写」，结构和方法可以学，台词、素材、独创表达不能搬

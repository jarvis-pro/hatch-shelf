# 完整拆解一个对标账号

上一章的两张表，单看格式很容易，真正填的时候会遇到很多具体问题：某一列到底写多细、高低怎么划线、规律怎么下结论。这一章用一个账号从头到尾填一遍。

**说明：本章的账号「表格不加班」及其全部作品、数据、评论都是虚构的**，为了演示拆解方法而编写，不对应任何真实账号。数字只用于演示计算过程，不代表平台的真实水平。真实拆解时，请换成你自己对标池里的账号。

示例的背景接第 1 章的一页定位卡：一位在职后端开发者，想做「给天天跟表格打交道的上班族讲用 AI 少加班的办法」，主平台抖音，不出镜录屏。「表格不加班」是他对标池里的一个腰部账号。

## 第一步：账号层拆解

```text
【账号层拆解】  账号：表格不加班（虚构）  平台：抖音  拆解日期：2026-11-03  层级：腰部

一、定位
  人群（从评论区推断）：行政、财务助理、运营、HR；评论里常见「我们领导」「月底对账」「入职第一年」
  需求：处理重复的表格工作，少加班；次要需求是在领导面前「显得会」
  形式：不出镜；电脑录屏 + 女声配音 + 大字幕
  人设句（替它写）：我是做了 6 年财务的表格熟手，因为天天被报表追着跑，
                   所以只讲上班族马上能用的表格技巧

二、包装
  名字：表格不加班（结构：领域词「表格」+ 结果「不加班」）
  头像：绿色底上一个白色表格图标，没有人脸
  简介：「6 年财务｜每天一个表格技巧｜Excel / WPS 都讲｜工作日 19:00 更新」
  背景图：一张带网格线的浅绿色图，写着「收藏 = 学会」
  置顶：3 条，都是历史点赞最高的：合并多表、一键对账、数据透视表入门
  合集：「5 分钟函数」42 条 / 「月底对账」17 条 / 「AI 做表」9 条（最新开的）

三、更新
  最近 30 天发布数：22 条（工作日基本每天一条）
  固定栏目：三个合集，周五固定发一条「本周问答」
  单条时长分布：多数 35–60 秒；问答类 90 秒左右

四、变现
  看得到的变现动作：橱窗里有一个付费模板包；最近 20 条里有 2 条带广告合作标识（办公软件）
  变现内容占比：约 10%

五、一句话总结
  最值得学：每条只解决一个具体场景，开头直接复述领导或同事的原话
  学不来的：6 年财务的真实经历和大量真实报表场景
```

账号层拆完，有一个信号值得注意：它最新开的合集是「AI 做表」，只有 9 条。说明这个账号自己也在往 AI 方向试，但还没形成优势。这对我们是机会，也是警告：AI 做表这个方向，腰部账号已经开始进来了。

| H1 | 领导要汇总 30 个表，5 分钟搞定 | 痛点解决 | 45s | 4.6 万（17.7 倍，高） |

## 第三步：作品层逐条拆

篇幅原因，这里完整展示一高（H1）一低（L1）两条，其余 13 条只列结论。

### H1：领导要汇总 30 个表，5 分钟搞定

| 列 | 内容 |
|---|---|
| 数据 | 赞 4.6 万 / 评 2100 / 藏 3.8 万 / 转 9400；高 |
| 选题 | 领导临时让你把 30 个分表汇总成一个总表 |
| 选题类型 | 痛点解决 |
| 标题与封面字 | 封面：「30 个表 → 1 个表」；标题：「领导让下班前交，你还在一个个复制？」 |
| 开头 3 秒 | 台词：「领导让你下班前把 30 个表汇总好？」画面：文件夹里 30 个 Excel 文件铺满屏幕 |
| 结构 | 0–3s 复述场景 / 3–8s 展示汇总后的结果表 / 8–38s 三步操作（新建查询 → 选文件夹 → 合并） / 38–45s 提醒「源文件更新后点刷新就行」+ 引导收藏 |
| 节奏 | 45 秒；切 14 次，平均每个镜头约 3.2 秒；台词 195 字，约 260 字/分钟 |
| 画面 | 录屏；每步操作时局部放大到鼠标位置；黄底黑字大字幕，关键按钮名称红框 |
| 结尾 / 行动引导 | 「先收藏，下次领导找你就用得上」 |
| 评论区高频词 | 「WPS」「Mac」「文件格式不一样」「表头不一致」「求模板」 |
| 变现挂载 | 无 |
| 我的判断 | 选题是高频且有时间压力的场景；开头复述领导原话；第 3 秒就给结果，观众知道「看完能得到什么」；收藏远高于点赞，说明是「以后要用」的工具型内容 |

### L1：函数嵌套的原理

| 列 | 内容 |
|---|---|
| 数据 | 赞 0.9 千 / 评 41 / 藏 1.1 千 / 转 60；低 |
| 选题 | 讲 IF 嵌套 VLOOKUP 时公式是怎么一层层计算的 |
| 选题类型 | 原理讲解 |
| 标题与封面字 | 封面：「函数嵌套原理」；标题：「搞懂这个，函数再也难不倒你」 |
| 开头 3 秒 | 台词：「今天我们来讲讲函数嵌套的原理。」画面：一个空白表格 |
| 结构 | 0–10s 介绍什么是嵌套 / 10–60s 拆解公式计算顺序 / 60–85s 一个例子 / 85–92s 总结 |
| 节奏 | 92 秒；切 11 次，平均每个镜头约 8.4 秒；台词 380 字，约 248 字/分钟 |
| 画面 | 录屏，无局部放大；字幕较小 |
| 结尾 / 行动引导 | 「你学会了吗？」 |
| 评论区高频词 | 「没听懂」「太快了」「有没有具体例子」 |
| 变现挂载 | 无 |
| 我的判断 | 选题没有具体场景，观众不知道什么时候用得上；开头是「今天我们来讲」，前 10 秒没有任何结果；镜头切换慢，画面长时间静止 |

注意语速：H1 和 L1 的语速差不多（260 和 248 字/分钟），差别在**镜头切换频率**（3.2 秒和 8.4 秒一切）和**结果出现的时间**（第 3 秒和第 60 秒之后）。如果只凭感觉，很容易得出「L1 讲得太慢」的错误结论。

## 第四步：评论区拆解

取 H1 按热度排序的前 100 条评论，分类计数（虚构）：

| 类别 | 条数 | 代表评论 |
|---|---|---|
| 需求延伸 | 21 | 「表头不一样的怎么合并」「能不能按月份分开汇总」 |
| 适用性疑问 | 26 | 「WPS 没有这个按钮」「Mac 版找不到」 |
| 求资源 | 9 | 「求练习文件」「有模板吗」 |
| 共鸣 | 18 | 「上周刚手动复制了一下午」「我们领导也这样」 |
| 质疑 / 纠错 | 7 | 「数据量大会卡」「用 Python 更快」 |
| 无效 | 19 | 表情、@好友 |

最显眼的是「适用性疑问」：26 条在问 WPS 和 Mac。再看 L2「Excel 和 WPS 的 10 个区别」数据很低，说明**观众要的不是两者的对比，而是「我手上这个软件怎么做」**。这条信息比任何技巧都值钱。

## 第五步：从表到规律

### 高低对比

「高的几条」指 R3 H1–H5，「低的几条」指 L1–L3，逐列比较它们的共同点：

- **选题类型**
  - 高的几条：具体职场场景，带时间压力或领导
  - 低的几条：原理、对比、个人分享，没有场景
  - 是不是原因：6 条高的里 4 条是场景型痛点解决，另 2 条（H3「看这一条就够了」、H4「入职第一天」）也绑定了明确的使用时机；3 条低的都没有，可以算规律
- **开头 3 秒**
  - 高的几条：复述场景或直接说出痛点
  - 低的几条：「今天讲」「分享我」
  - 是不是原因：是
- **结果出现时间**
  - 高的几条：第 2–6 秒
  - 低的几条：第 10 秒以后
  - 是不是原因：是
- **平均镜头时长**
  - 高的几条：2.5–4 秒
  - 低的几条：6–8.4 秒
  - 是不是原因：是
- **时长**
  - 高的几条：39–72 秒
  - 低的几条：66–92 秒
  - 是不是原因：有相关，但 H3 有 72 秒，不能说「越短越好」
- **收藏 / 点赞**
  - 高的几条：高的几条收藏普遍接近或超过点赞
  - 低的几条：无明显规律
  - 是不是原因：说明是工具型内容，记下来，不算原因

### 跨账号汇总

假设对另外 4 个腰部对标也做了同样的拆解（过程略），汇总如下：

```text
【跨账号规律汇总】  赛道：上班族表格 / AI 提效  汇总日期：2026-11-03

在 4–5 个对标里都出现的（大概率是赛道规律）：
  - 选题以「具体职场场景 + 时间压力」为主，原理类普遍数据低
  - 第 5 秒内给出结果画面
  - 录屏 + 局部放大 + 大字幕，平均 3 秒左右切一次
  - 结尾引导收藏，而不是引导关注

只在 1–2 个对标里出现的（可能是个人风格）：
  - 女声配音（表格不加班）
  - 每周五固定问答栏目
  - 开头加一段固定音效

所有对标都没做、评论区却有人要的（机会）：
  - 每个技巧同时给出 WPS 和 Mac 的做法（评论区反复在问，5 个对标都只演示 Windows Excel）
  - 「AI 做表」只有一个对标刚开始做，且没有讲清楚哪些 AI 工具免登录、哪些要付费
  - 表头不一致、格式混乱这类「脏数据」场景很少有人讲
```

## 第六步：变成你自己的定位

拆解的产出要回到一页定位卡。这位开发者根据拆解结果做了三处调整：

| 定位卡项 | 拆解前 | 拆解后 | 依据 |
|---|---|---|---|
| 账号一句话 | 给上班族讲用 AI 少加班的办法 | 给上班族讲用 AI 处理「乱七八糟的表格」，Excel、WPS、Mac 都讲 | 机会栏的第 1、3 条 |
| 人设句 | 只讲马上能用的办法 | 程序员视角：先讲为什么这张表会乱，再用 AI 一次性理干净 | 和财务背景的对标做出区分，用自己真实的专长 |
| 内容边界 | 不讲概念 | 不讲原理课；每条必须从一个具体场景开始，第 5 秒给结果 | 高低对比 |

然后用结构仿写写出第一条的骨架：

```text
【第一条骨架】

选题：同事发来 12 个表，表头每个都不一样，怎么合成一个
类型：痛点解决（场景型）
开头 3 秒：「同事发来 12 个表，表头还都不一样？」画面：12 个表头并排，列名各不相同
3–6s：直接展示合并后整齐的总表
6–40s：
  ① 把 12 个表头复制给 AI，让它生成统一的列名对照（提示词全文上屏）
  ② WPS 里的做法
  ③ Mac Excel 里的做法
40–45s：「练习文件放在合集第一条的评论区说明里，先收藏」
         （注：不在评论区留外部链接或联系方式，导流规则见《国内私域与内容平台》第 5 章）

差异检查：
  - 选题：对标没讲过表头不一致的场景                   是
  - 台词：全部自己写                                   是
  - 画面：全部自己录，用自己造的虚拟数据，不用公司真实报表   是
```

最后一行很重要：在职开发者录屏时，**一律用自己编的演示数据**，不要用任何公司的真实表格，哪怕打了码。

## 这次拆解花了多少时间

给一个参考，便于你安排周末：

| 步骤 | 时间 |
|---|---|
| 账号层拆解 | 30 分钟 |
| 采样 15 条并记录数据 | 20 分钟 |
| 两条完整拆解（含转写、计时、数镜头） | 每条约 25 分钟，共 50 分钟 |
| 其余 13 条简要拆解 | 每条约 6 分钟，共 80 分钟 |
| 评论区分类计数 | 30 分钟 |
| 高低对比与结论 | 30 分钟 |
| **合计** | **约 4 小时** |

5 个腰部对标都这样拆，大约 20 小时，正好两个周末。熟练以后，单个账号能压到 2 小时左右。

## 本章要点

- 本章的「表格不加班」是虚构示例，用于演示；真实拆解请换成你对标池里的账号
- 「高低」统一用相对中位数的倍数来划，一个赛道内阈值要统一
- 只凭感觉容易归错因：H1 和 L1 语速接近，真正的差别是镜头切换频率和结果出现的时间
- 评论区的「适用性疑问」常常比技巧本身更有价值，它直接指向对标没覆盖的人群
- 规律要跨账号验证：多个对标都有的是赛道规律，只有一两个有的是个人风格，都没做但评论区要的是机会
- 拆解的产出要回写到一页定位卡，并落成第一条内容的骨架；录屏只用自己编的演示数据

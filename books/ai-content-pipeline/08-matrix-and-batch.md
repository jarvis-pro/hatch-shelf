# 矩阵与批量

流水线跑通之后，下一个念头几乎是必然的：既然一条内容的边际成本这么低，为什么不一天做十条、开十个号？这就是「矩阵」和「批量」。这一章讲它们什么时候有意义、产能和质量怎么平衡、平台怎么对待同质化内容，以及一套可以照着执行的批量生产 SOP。

先说结论：**批量生产的上限由审核能力决定，不由生成能力决定；矩阵的价值来自差异化，不来自数量。** 做反了，就是平台专项治理的对象。

## 矩阵的几种形态

| 形态 | 做法 | 合理性 |
|---|---|---|
| 多平台分发 | 同一个人、同一批内容，按平台改写后发到抖音、小红书、视频号、B 站 | 最常见也最稳妥，每个平台一个号 |
| 主号 + 切片号 | 主号发完整内容，切片号发直播、长视频的精华片段 | 合理，前提是切的是自己的内容 |
| 垂类细分 | 一个大赛道拆成几个细分号，各有定位和受众 | 合理，但每个号都要有独立的内容规划 |
| 地域 / 门店矩阵 | 连锁品牌每家门店一个号 | 合理，内容有真实的门店差异 |
| 同质化铺号 | 同一套模板、同一种素材，开几十个号碰运气 | 平台重点打击 |

前四种的共同点是：**每个号都有存在的理由**，要么平台不同，要么受众不同，要么内容不同。第五种的唯一理由是「多买几张彩票」，而平台恰恰在识别和打击这种行为。

## 平台怎么看同质化和批量

平台规则的原文要点见第 10 章，这里只列和批量直接相关的：

- **小红书**：2026 年 4 月发布的 AI 内容治理规则，把「套用模板批量生产同质化内容」列为 AI 低质内容，把「利用 AI 工具自动运营账号、冒充真人互动」和「传授 AI 洗稿、规避审核的做号方法」列为 AI 违规运营，处置包括限制分发、封禁账号等
- **抖音**：2025 年 5 月开展「AI 起号」专项治理，针对利用 AI 造假、批量起号和贩卖 AI 账号；公告同时重申，以任何形式赠与、借用、出租、转让、售卖账号都是违规行为
- **各平台的原创保护和搬运识别**：内容高度相似的，平台会判定为非原创或重复内容，通常只有最早或最原创的那一条能获得正常分发

从推荐系统的角度理解：平台要的是用户刷到的内容足够多样。十个号发十条几乎一样的视频，对平台来说只是在消耗推荐位，没有给用户带来新东西，降权是合乎逻辑的。所以「怎么不被识别」是一个错的问题，对的问题是「怎么让每一条都值得被推荐」。

## 产能由审核决定

AI 让生成的成本接近零，但审核的成本没有变。一条 60 秒的视频，认真看一遍成片、过一遍清单、核对事实，至少 10–20 分钟。

$$
\text{每周可发布上限} = \frac{\text{每周可用于审核的时间}}{\text{每条审核时间}}
$$

如果你每周能拿出 5 小时专门审核，每条认真审核 15 分钟，上限就是 20 条。超过这个数，要么审核开始走过场，要么你需要请人审核。**任何超过审核产能的生产都是在积累风险**：一条带错误事实、侵权素材或漏了标识的内容，可能比十条好内容带来的收益更大地伤害账号。

这个公式还告诉你另一件事：想提高产能，优化的重点是**让审核更快**而不是让生成更快。办法包括：

- 把能自动化的检查都写成检查器（第 7 章），人只看机器判断不了的
- 审核页把关键信息（事实清单、检查器警告、标识位置的截图）集中展示，不用翻来翻去
- 同一类内容集中审核，进入状态后效率高很多
- 分级审核：同一模板的第 N 条，前几条全面审，稳定后重点看变化的部分（但成片至少完整看一遍，这一项不能省）

## 差异化：每个号、每一条的存在理由

### 差异化的维度

| 维度 | 低差异 | 高差异 |
|---|---|---|
| 选题 | 同一个热点所有号都做 | 每个号有自己的选题库和受众问题 |
| 素材 | 都用 AI 生成的通用画面 | 有自己的实拍、截图、数据、案例 |
| 观点 | 「正确的废话」 | 有立场、可被反驳 |
| 人设和声音 | 同一个热门 TTS 音色 | 固定的真人或授权音色，固定的说话风格 |
| 画面风格 | 平台模板 | 自己的风格卡和版式模板 |
| 结构 | 同一个模板套到底 | 几种结构轮换，按选题选结构 |

一个矩阵里如果每个号在以上维度都高度相似，那它不是矩阵，是复印机。

### 用代码检查相似度

做批量时，可以在流水线里加一道相似度检查：新脚本和最近发过的脚本比一比，太像就提醒。下面是一个简单的字符 n-gram Jaccard 相似度实现（示例代码，未在生产环境跑过）：

```ts
// similarity.ts
function grams(text: string, n = 3): Set<string> {
  const clean = text.replace(/[\s，。！？、；：「」“”‘’（）,.!?;:()]/g, "");
  const set = new Set<string>();
  for (let i = 0; i + n <= clean.length; i++) set.add(clean.slice(i, i + n));
  return set;
}

export function jaccard(a: string, b: string): number {
  const A = grams(a), B = grams(b);
  let inter = 0;
  for (const g of A) if (B.has(g)) inter++;
  return inter / (A.size + B.size - inter || 1);
}

/** 返回和新稿最相似的若干条历史稿 */
export function nearest(newScript: string, history: { id: string; text: string }[], k = 3) {
  return history
    .map((h) => ({ id: h.id, score: jaccard(newScript, h.text) }))
    .sort((x, y) => y.score - x.score)
    .slice(0, k);
}
```

阈值没有标准答案，要用你自己的数据定：拿 20 对你认为「明显重复」和 20 对「同主题但不重复」的稿子跑一遍，看分数分布在哪里分开。字符 n-gram 只能发现措辞层面的相似，换个说法的「结构性重复」它发现不了，可以再加一道用嵌入向量算语义相似度的检查。

这个检查的目的不是「骗过平台的判重」，而是**提醒自己**：如果你自己的检查器都觉得这两条太像，观众和平台更会这么觉得。

## 批量生产 SOP

下面是一个人做「1 个主号 + 3 个平台分发」、每周 10 条原创内容的一周节奏。时间按一个有全职工作的人业余投入估算，按自己的情况调整。

| 时间 | 做什么 | 产出 | 用时 |
|---|---|---|---|
| 周日晚 | 复盘上周数据，读评论区，跑选题归纳模板 | 上周数据表、候选选题 20–30 个 | 1 小时 |
| 周一 | 选题打分，选 10 个；每个写素材卡 | 10 张素材卡 | 1.5 小时 |
| 周二 | 流水线批量生成脚本；关卡 1：逐条改稿、念稿、核事实 | 10 条定稿脚本 | 2.5 小时 |
| 周三 | 流水线批量生成配音、配图、字幕、合成；挑图、补拍或补录 | 10 条初版成片 | 1.5 小时（多数时间在等） |
| 周四 | 关卡 2：逐条看成片、过清单；退回的修改 | 10 条定版 | 2.5 小时 |
| 周五 | 跨平台改写标题、简介，准备待发布包，排期 | 40 个待发布包 | 1 小时 |
| 每天 | 按排期发布，回复评论 | | 每天 20–30 分钟 |

几个关键点：

- **批量做同一个环节**。周二只写稿、周四只审片，比每条从头做到尾效率高得多，也更容易保持标准一致
- **关卡时间要预留足**。表里关卡 1 和关卡 2 一共占了 5 小时，是整周最大的投入。如果某周时间不够，砍的是条数，不是审核
- **素材卡是瓶颈**。每周 10 张有真材实料的素材卡，比生成 10 条脚本难得多。素材卡写不出来，说明这周的条数定高了

### 什么时候加量

不要一开始就做 10 条。一个稳妥的节奏：

1. 每周 3 条，手工做，直到连续 4 周有稳定的数据基线
2. 流水线接管重复步骤，保持每周 3 条，确认数据没有下降
3. 每周加 2 条，每次加量后观察 2 周：完播率、互动率、负反馈（不感兴趣、举报）有没有恶化
4. 一旦数据恶化或审核开始赶工，退回上一档

数据下降时，第一反应应该是减量和回查质量，而不是「再多发一点碰碰运气」。

## 多平台分发

一份内容发多个平台，是矩阵里最稳妥、性价比最高的形态。要点：

| 事项 | 做法 |
|---|---|
| 改写 | 按平台改标题、简介、话题、封面，图文平台改成图文（第 2 章模板四） |
| 尺寸时长 | 竖屏 9:16 通用；B 站可以出横屏长版本；按各平台主流时长剪不同版本 |
| 首发和原创声明 | 选一个主平台首发并声明原创，其他平台随后发布 |
| 音乐 | 平台曲库的授权一般只限本平台，换平台要换音乐或用自有授权音乐 |
| 水印 | 不要把带 A 平台水印的视频发到 B 平台，用无水印的原始导出文件 |
| AI 声明 | 每个平台都要单独勾选，各平台入口不同 |
| 数据 | 分平台记录，同一条内容在不同平台的表现差异本身就是选题信息 |

各平台的推荐逻辑和内容形态差别，见[《抖音与快手》](../douyin-kuaishou/)[《小红书、视频号与 B 站》](../xhs-channels-bilibili/)。

## 矩阵的账号合规

做多账号时，账号本身也有规则：

- **实名和数量限制**：各平台对一个身份能注册、认证几个账号有不同规定，以平台规则为准；企业号和个人号的规则也不同
- **不买卖、不租借账号**：抖音公告明确，以任何形式赠与、借用、出租、转让、售卖账号均属违规；买来的号还可能带着前任的违规记录
- **不用群控和改机**：一台设备批量操控几十个号、修改设备信息规避识别，是各平台打击的典型异常行为
- **账号主体**：签了 MCN 的，看清合同里关于账号归属和矩阵号的条款（见[《广告商单与品牌合作》](../brand-deals/)[《自媒体与短剧合规财税》](../media-compliance/)）

## 质量监控

批量生产要有一个看板盯着质量，至少看这几个指标，按账号、按周看趋势：

| 指标 | 看什么 |
|---|---|
| 完播率、平均播放时长 | 内容是否还吸引人；批量后常见的是这个先掉 |
| 互动率（评论、收藏、分享） | 内容是否有价值和讨论度 |
| 负反馈 | 「不感兴趣」、举报、取关，平台后台通常能看到 |
| 评论区关键词 | 「AI 做的吧」「又是这种」出现频率 |
| 单条播放的分布 | 是否突然整体下降，可能是账号被限流的信号 |
| 审核退回率 | 关卡 2 退回的比例，太低可能是审核在走过场 |

评论区里「一看就是 AI」这类评论，是最便宜的质量反馈。可以用大模型每周归纳一次评论区，单独统计这类评论的比例。

## 常见坑

| 坑 | 表现 | 怎么办 |
|---|---|---|
| 单号没跑通就开矩阵 | 每个号都半死不活 | 主号有稳定数据基线后再扩 |
| 按生成能力定产量 | 审核走过场，事故频出 | 按审核时间算上限 |
| 同一模板铺多个号 | 判重、限流、专项治理 | 每个号有独立选题、素材、风格 |
| 加量太快 | 数据下滑才发现 | 每次加量观察 2 周，恶化就退回 |
| 带水印跨平台发 | 被判搬运 | 用无水印原始文件 |
| 买号起量 | 违规，号还可能带历史问题 | 自己养号 |
| 只看总播放 | 看不到某个号被限流 | 按账号、按周看趋势和负反馈 |

## 本章要点

- 合理的矩阵是多平台分发、主号加切片号、垂类细分、地域矩阵，每个号都有存在的理由；同质化铺号是平台打击对象
- 小红书把模板化批量同质化内容列为 AI 低质，抖音专项治理 AI 批量起号和账号买卖；该问的是每一条凭什么值得推荐，而不是怎么不被识别
- 每周发布上限等于审核时间除以每条审核时间；提高产能要让审核更快，时间不够时砍条数不砍审核
- 从选题、素材、观点、人设声音、画面、结构六个维度做差异化，用相似度检查提醒自己避免重复
- 按环节批量作业，素材卡是真正的瓶颈；加量要循序渐进，数据恶化就退回
- 多平台分发要改写、换音乐、去水印、分别声明 AI；不买卖账号、不用群控
- 看板按账号看完播、互动、负反馈和审核退回率的趋势

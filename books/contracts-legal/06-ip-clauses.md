# 知识产权条款

对一人公司来说，产品几乎就是全部资产：代码、设计、品牌、数据。这些东西归谁，大多数时候不是在登记的时候决定的，而是在**合同里**决定的：你跟前东家的劳动合同、你跟自己公司之间的转让协议、你跟外包设计师的合同、你跟定制客户的合同、你跟 SaaS 客户的服务协议。

软件著作权怎么登记、商标怎么申请，见[《国内合规实务》第 5 章](../opc-compliance-cn/05-software-copyright.md)「软件著作权与商标」；在职期间做副业的成果归属，见[《一人公司方法论》第 4 章](../opc-playbook/04-side-to-fulltime.md)「从副业到全职」。这一章只讲合同里的知识产权条款：默认规则是什么、转让和许可怎么写、定制功能和 SaaS 产品的边界、开源和 AI 生成内容，以及侵权担保。

## 先记住默认规则

合同没写的时候，法律按下面的规则分配权利。这些默认规则常常和直觉相反：

| 情形 | 默认归属 | 依据 |
|---|---|---|
| 委托他人创作的作品（设计稿、插画、文案） | 合同未明确约定或者没有订立合同的，**归受托人** | 《著作权法》第十九条 |
| 委托他人开发的软件 | 无书面合同或者合同未明确约定的，**归受托人** | 《计算机软件保护条例》第十一条 |
| 委托开发完成的发明创造 | 申请专利的权利属于**研究开发人**，委托人可以依法实施该专利 | 《民法典》第八百五十九条 |
| 委托开发的技术秘密成果 | 没有约定或约定不明的，双方均有使用和转让的权利；研究开发人在交付前不得转让给第三人 | 《民法典》第八百六十一条 |
| 员工为完成工作任务创作的作品 | 一般归作者，单位在业务范围内优先使用；特定情形归单位 | 《著作权法》第十八条 |

两条结论：

1. **你花钱请别人做的东西，不写合同就不是你的**。这是一人公司最常见的知识产权漏洞
2. **著作权中的人身权利不能转让**。《著作权法》第二十七条规定，转让第十条第一款第（五）项至第（十七）项规定的权利（复制权、发行权、信息网络传播权、改编权等财产权利）应当订立书面合同；发表权、署名权、修改权、保护作品完整权这几项人身权利不在可转让之列。所以合同里常见的写法是「转让全部著作权财产权利，并且作者同意不行使署名权」，而不是「转让全部著作权」

## 转让还是许可

| | 转让 | 许可 |
|---|---|---|
| 效果 | 权利换了主人 | 权利人不变，对方获得使用的权利 |
| 形式 | 应当订立书面合同（《著作权法》第二十七条） | 订立许可使用合同（第二十六条），要写明权利种类、是否专有、地域、期间等 |
| 对方能否再许可他人 | 能，权利已经是他的 | 看合同约定 |
| 你还能不能用 | 不能（除非约定保留） | 能（非专有许可时） |
| 适用场景 | 客户买断定制系统；你从设计师那里买 Logo | SaaS 服务；你的通用组件嵌在客户系统里 |

另外，《著作权法》第二十九条规定：许可使用合同和转让合同中著作权人未明确许可、转让的权利，未经著作权人同意，另一方不得行使。**没写的就是没给**。合同里只写「转让设计稿的著作权」，对方会主张你没拿到改编权，不能自己改 Logo 的配色。所以权利种类要写全，或者写「全部著作权财产权利」。

## 你和你自己的公司

很多一人公司的产品是先以个人身份写出来的，后来才注册公司。这时代码的著作权在你个人名下，公司要以自己的名义登记软著、签客户合同、上架 App，就需要从你手里拿到权利。这是一份很多人忽略、但非常值得签的合同：

```text
软件著作权转让协议

转让方：张三（身份证号：＿＿＿＿）
受让方：某某科技有限公司（统一社会信用代码：＿＿＿＿）

第 1 条　转让方将其独立开发的「掌柜眼门店经营管理软件」（包括截至本协议
签订之日的全部源代码、文档、设计稿，以下简称「本软件」）的全部著作权
财产权利转让给受让方，包括但不限于复制权、发行权、出租权、信息网络
传播权、翻译权、改编权，以及其他应当由著作权人享有的财产权利。
第 2 条　转让的地域范围为全世界，期限为著作权保护期内。
第 3 条　转让价款为人民币＿＿元（或：转让方以本软件著作权作价向受让方
出资，具体以股东决定为准）。
第 4 条　转让方保证本软件为其独立开发，不侵犯任何第三方的合法权益；
本软件中使用的开源组件依照其许可证使用，清单见附件。
第 5 条　转让方同意在本软件上以受让方名义署名，并不再行使署名权。
第 6 条　本协议签订后，转让方配合受让方办理软件著作权登记或者变更登记。
```

第 3 条的价款是一个需要想清楚的问题：0 元转让、象征性价款、还是作为出资，涉及税务和公司资本的处理，问一下你的代账会计（见[《财务与税务》](../opc-finance/)）。第 4 条要求你自己确认代码没有侵权问题，包括你在职期间是否用了前东家的代码，这一点跟《一人公司方法论》第 4 章讲的劳动合同知识产权条款直接相关。

## 你作为客户：找人做东西

### 设计稿和 Logo

找设计师做 Logo、官网插画、App 图标，是一人公司最常见的发包。合同可以很短，但下面几项必须有：

```text
第 X 条　知识产权
X.1 乙方为本项目创作并经甲方验收的最终设计稿（包括源文件）的全部著作权
    财产权利，自甲方付清全部费用之日起转让给甲方。甲方有权对设计稿进行
    修改、改编，用于任何商业用途，并以其申请商标注册。
X.2 乙方同意不就上述设计稿行使署名权；乙方可以在其个人作品集中展示
    设计稿，但应在甲方产品公开发布之后，且不得展示未公开的甲方产品信息。
X.3 乙方保证设计稿为其原创，未使用未经授权的字体、图片、素材。设计稿中
    使用的字体、素材应列明来源和授权方式；需要甲方另行购买授权的，乙方
    应在交付前告知。
X.4 未被甲方选用的方案稿，著作权仍归乙方，但乙方不得将其中明显体现甲方
    品牌特征的元素用于其他客户。
```

几个容易出问题的地方：

- **Logo 要申请商标**，商标申请需要你对图样有合法权利。没有 X.1 的转让，就存在「图形商标侵犯他人著作权」的风险
- **字体授权**是设计稿里最常见的雷。设计师用了一款商用字体做 Logo 文字，你拿去注册商标、印在物料上，字体厂商找上门。X.3 要求设计师列明字体来源，最好用免费商用字体或者你自己购买的授权
- **作品集展示**是设计师的正常诉求，直接禁止会让好的设计师不愿意接；X.2 给了一个折中

### 代码

找人写一个原生模块、一个数据迁移脚本，同样要写清楚归属。除了第 4 章外包合同里的条款，还要特别注意对方带进来的东西：

```text
乙方交付的代码中如包含乙方既有代码、第三方代码或者开源组件，乙方应在
交付时列明清单。未列明的，视为乙方为本项目专门编写，其著作权依照本合同
约定归甲方。乙方不得在交付代码中包含使用 GPL、AGPL 等要求衍生作品
开源的许可证的组件，经甲方书面同意的除外。
```

最后一句对 SaaS 尤其要紧。hatch-counter 是私有项目，如果外包写的模块里混进了强传染性许可证的代码，你就面临要么开源、要么替换的选择（关于开源许可证的检查方法，见《国内合规实务》第 5 章）。AGPL 对通过网络提供服务的场景也有开源要求，对 SaaS 尤其不友好。

## 你作为供应商：定制功能和 SaaS 产品的边界

这是本章最重要的部分。当一个连锁客户说「我们想加一个功能，我们出钱」，问题来了：这个功能做进 hatch-counter 之后，归谁？

如果按第 4 章外包合同的默认写法「定制成果归甲方」，你就把自己产品的一部分卖掉了：这个功能以后不能给其他门店用，甚至你的主干代码里嵌着一段别人的代码。对 SaaS 来说，这几乎不可接受。

正确的结构是**区分两种模式**，签约之前就跟客户说清楚：

| | 模式一：产品内定制 | 模式二：独立交付 |
|---|---|---|
| 做法 | 功能做进 SaaS 产品，所有门店都能用（或者按开关只对该客户开放） | 单独开发一个系统或模块，交付给客户自己部署 |
| 知识产权 | 归你，客户获得使用权 | 可以归客户 |
| 价格 | 较低，因为你也受益 | 较高，因为成果归客户 |
| 合同 | 服务协议的补充协议 | 外包开发合同（第 4 章） |

hatch-counter 这类产品几乎都应该走模式一：

```text
补充协议　定制功能
第 1 条　应甲方需求，乙方在「掌柜眼」中开发「多门店调拨」功能（需求见附件），
甲方支付开发费用人民币＿＿元。
第 2 条　该功能作为「掌柜眼」的组成部分，其全部知识产权归乙方所有。乙方
有权将该功能提供给其他客户使用。
第 3 条　作为对甲方承担开发费用的回报，乙方给予甲方以下权益：
    （1）该功能上线后十二个月内，乙方不向甲方所在城市的其他连锁餐饮客户
        单独开放该功能（以本服务所有客户都可使用的形式开放的除外）；或
    （2）甲方在服务协议项下的服务费享受＿＿折优惠，期限＿＿年。
第 4 条　甲方在需求沟通中提供的业务流程、单据样式、经营数据，属于甲方的
保密信息，乙方不得向其他客户披露；但乙方基于此开发的通用功能设计不受
此限制。
```

第 3 条是谈判的筹码：客户出了钱，总想要点独占的东西。给一段时间的有限独占或者价格优惠，比给知识产权便宜得多。第 4 条把「客户的信息」和「你做出来的功能」分开，前者保密，后者归你。

### 客户的反馈和建议

SaaS 客户会提很多建议，有的被你做成了功能。为了避免将来有人主张「这个功能是我想出来的」，服务协议里加一条：

```text
甲方就本服务提出的意见、建议，乙方可以无偿用于改进本服务，由此形成的
成果归乙方所有，乙方无需就此向甲方支付费用或者承担其他义务。
```

这条在实践中很少引发争议，但写上没有坏处。

### 客户数据和衍生数据

第 2 章说过客户数据归客户。这里补充一个边界问题：基于客户数据**加工出来的东西**归谁？

| 数据 | 建议的归属 |
|---|---|
| 门店录入的原始数据 | 门店 |
| 本服务为该门店算出来的报表、分析结果 | 门店（第 2 章 8.1 已经写了） |
| 服务运行数据（访问量、功能使用率、耗时、错误） | 你，不能识别到门店和个人 |
| 跨门店的匿名化统计（比如「某城市川菜馆平均毛利」） | 需要明确约定；不约定就不要做 |
| 你为识别进货单调整的提示词、模板、规则 | 你 |

最后一行值得说一句：hatch-counter 的「按模板逐行取数」需要为不同供应商的单据配置模板。这些模板是你的工作成果，即使它们是在处理某个门店的单据时调出来的。在服务协议里写明「乙方为提供本服务形成的识别模板、规则和配置归乙方所有」，避免门店解约时要求带走。

## 开源组件

几乎所有软件都用了开源组件，合同里要处理两件事：

1. **你交付给客户的东西里有开源组件**：列清单，说明按其许可证使用，客户要遵守许可证（比如保留版权声明）
2. **你对开源组件不做超出许可证的担保**：开源组件本身的缺陷、安全漏洞，你会尽力修复或更新，但不承担开源作者都不承担的保证责任

```text
交付物中包含的开源软件依照其各自的许可证提供，清单见附件。乙方不就开源
软件本身作出超出其许可证的保证，但乙方应在知悉开源软件存在影响交付物
安全的漏洞后，在维护期内及时更新或者采取缓解措施。
```

## AI 生成内容

你用编码 agent 写代码、用图像模型画插画，这些产出的权利归属在法律上还在发展中。可以确定的方向是：著作权保护人的智力成果，人在其中的投入（构思、选择、修改、整合）越多，越可能构成受保护的作品；司法实践中既有认定 AI 辅助生成的内容构成作品的判决，也有因为人的智力投入不足而不予认定的。具体到一个案件怎么判，取决于证据和法院的判断。

面对这种不确定，合同能做的是**分配风险**，而不是假装问题不存在：

```text
第 X 条　人工智能工具的使用
X.1 乙方在履行本合同过程中可以使用人工智能辅助工具，但应对交付成果进行
    审查、修改和测试，并对交付成果的质量承担与人工完成相同的责任。
X.2 乙方保证交付成果不包含其明知或者应知侵犯第三方权利的内容。
X.3 交付成果中由人工智能工具生成的部分，在法律允许的范围内，其权益依照
    本合同关于知识产权归属的约定归属。双方确认，某部分内容是否构成受法律
    保护的作品，不影响甲方依照本合同对交付成果的使用。
```

X.3 的后半句是关键：即使某段 AI 生成的代码最后被认定不构成作品、谁都不享有著作权，客户依照合同使用它也不受影响。这样客户的核心关切（我能不能用）得到了回应，而你也没有承诺一个法律上不确定的「保证享有著作权」。

你作为发包方时，反过来要求对方披露是否使用了 AI 工具、对生成内容做了哪些审查。对 Logo 这类要申请商标的设计，可以要求设计师说明创作过程，以便将来证明权利基础。

## 侵权担保：谁来兜底

你交给客户的东西被第三方说侵权，谁负责？

技术转让和许可合同里，法律有明确要求：《民法典》第八百七十条规定让与人、许可人应当保证自己是所提供技术的合法拥有者；第八百七十四条规定受让人、被许可人按约定实施时侵害他人合法权益的，由让与人或者许可人承担责任，另有约定的除外。

对 SaaS 和外包合同，通常的写法是：

```text
第 X 条　知识产权担保
X.1 乙方保证本服务（或交付物）不侵犯第三方的知识产权。第三方就此向甲方
    提出权利主张的，乙方应负责处理并承担由此产生的赔偿和合理费用，但甲方
    应及时通知乙方并配合处理。
X.2 下列情形不适用 X.1：侵权系因甲方提供的素材、数据、需求说明造成；甲方
    对交付物进行修改或者与其他软件组合使用造成；甲方超出约定范围使用。
X.3 发生 X.1 情形的，乙方可以选择为甲方取得继续使用的权利、修改交付物以
    避免侵权，或者在无法实现时终止相应部分的服务并退还对应费用。
```

X.2 的除外情形很重要：客户给你一张从网上随便找的图让你放进系统，被人告了，这不应该由你负责。X.3 给了你几种解决路径，避免唯一的选项是赔钱。

知识产权担保要不要受第 2 章责任上限的约束，是谈判中常见的争议点。客户通常希望不受限制；你可以接受不受限制，但前提是 X.2 的除外情形写得足够清楚。

## 审知识产权条款的清单

| 检查项 | 要看什么 |
|---|---|
| 默认规则 | 合同里写了归属吗？没写的话按默认规则对你有利还是不利 |
| 权利种类 | 转让或许可的权利写全了吗？「全部著作权财产权利」 |
| 人身权利 | 有没有「不行使署名权」的约定；作品集展示怎么处理 |
| 转让时点 | 是否随付款完成转移 |
| 既有成果 | 你（或对方）带进来的代码和素材有清单吗 |
| 定制与产品 | 定制功能是做进产品还是独立交付？归属与模式一致吗 |
| 反馈和衍生数据 | 建议的使用权；识别模板等配置归属 |
| 开源 | 有清单；限制强传染性许可证 |
| AI 生成 | 使用是否披露；权属不确定时使用权是否有保障 |
| 字体和素材 | 来源和授权是否列明 |
| 侵权担保 | 范围、除外、解决路径、是否受上限约束 |

## 常见的坑

- **找人做 Logo 没签合同**。商标申请、维权时拿不出权利来源
- **个人写的代码直接以公司名义登记**。公司如何取得权利说不清，以后融资、转让、纠纷时都是问题
- **定制功能写成「成果归甲方」**。等于把产品的一部分卖了
- **只写「转让著作权」**。人身权不能转让，财产权没写全，对方主张你没有改编权
- **设计稿里的商用字体**。用到品牌和商标上，被字体厂商追责
- **外包代码里混入 AGPL**。对 SaaS 产品影响尤其大
- **对 AI 生成内容承诺「保证享有完整著作权」**。法律上不确定的事不要做绝对承诺

## 本章要点

- 委托创作的作品、委托开发的软件，没有约定时归受托人：花钱请人做的东西一定要写明归你
- 著作权人身权利不能转让，合同写「全部著作权财产权利」加「不行使署名权」；转让要书面，没写明的权利就是没给
- 个人先写后成立公司的，签一份软件著作权转让协议，价款方式问代账
- 设计合同要处理商标用途、字体素材授权、作品集展示
- SaaS 的定制功能走「产品内定制」：知识产权归你，用有限独占或价格优惠回报出钱的客户
- 客户反馈、识别模板、服务运行数据的归属在服务协议里写明
- 开源组件列清单、不做超出许可证的担保，外包代码限制强传染性许可证
- AI 生成内容的权属不确定，合同里保障「使用不受影响」，不承诺「保证享有著作权」
- 侵权担保写清除外情形和解决路径

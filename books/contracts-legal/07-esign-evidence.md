# 电子签与存证

一人公司的合同大多是在线上完成的：客户在外地，不可能每单都快递纸质合同；外包、设计这类小单子，双方在微信里谈完就开工；用户协议更是只能在线点同意。这一章回答两个问题：**线上签的合同算不算数**，以及**出了纠纷时，怎么证明合同、聊天、交付、付款这些事真的发生过**。

后一个问题比前一个更重要。合同纠纷里，大部分时候双方争的不是法律怎么规定，而是事实：你有没有交付、对方有没有确认、哪个版本是最终版。证据留得好，很多纠纷根本打不起来。

## 电子合同的效力

### 法律基础

几条关键规定：

- 《民法典》第四百六十九条：以电子数据交换、电子邮件等方式能够有形地表现所载内容，并可以随时调取查用的数据电文，视为书面形式
- 《电子签名法》第三条：民事活动中的合同或者其他文件、单证等文书，当事人可以约定使用或者不使用电子签名、数据电文；当事人约定使用的，**不得仅因为其采用电子签名、数据电文的形式而否定其法律效力**。但涉及婚姻、收养、继承等人身关系的，涉及停止供水、供热、供气等公用事业服务的，以及法律、行政法规规定不适用的文书除外
- 《电子签名法》第十四条：可靠的电子签名与手写签名或者盖章具有同等的法律效力

一人公司碰到的合同（服务合同、外包合同、保密协议、用户协议）都不在除外范围内，用电子方式签署没有障碍。

### 什么是「可靠的电子签名」

《电子签名法》第十三条规定，电子签名同时符合下列条件的，视为可靠的电子签名：

1. 电子签名制作数据用于电子签名时，属于电子签名人专有
2. 签署时电子签名制作数据仅由电子签名人控制
3. 签署后对电子签名的任何改动能够被发现
4. 签署后对数据电文内容和形式的任何改动能够被发现

当事人也可以选择使用符合其约定的可靠条件的电子签名。

对照这四条，就能理解几种常见做法的强弱：

| 做法 | 能否满足四个条件 | 实务评价 |
|---|---|---|
| 第三方电子签平台（实名认证 + 意愿认证 + 数字证书签名） | 设计上就是为了满足 | 最稳；对方否认时平台能出具签署证据 |
| 双方在 PDF 上贴手写签名图片或公章图片，邮件往来 | 图片可以被任何人复制粘贴，第 1、2 条很难满足 | 不是「可靠的电子签名」，但邮件往来本身仍可作为合同成立的证据 |
| 打印、手签、扫描回传 | 本质是纸质签名的复印件 | 常见且被普遍接受，最好留有原件或后补原件 |
| 微信里回复「同意」「确认」 | 不是签名，但可以证明意思表示 | 配合身份证明，可以证明合同成立和条款内容 |
| 网站上勾选同意 | 不是签名，是以行为作出承诺 | 配合服务端记录，可以证明同意（第 3 章） |

关键是理解两个层次：**合同成立**不一定需要签名，邮件、微信、勾选都可以；**可靠的电子签名**的价值在于，当对方否认「这是我签的」时，你的举证负担要轻得多。

### 一人公司怎么选

| 合同 | 建议 |
|---|---|
| 门店服务协议（金额较大或连锁客户） | 第三方电子签平台，或纸质双签 |
| 门店服务协议（单店小额） | 电子签平台，或在线确认 + 订单付款（第 2 章的订单结构）|
| 外包开发合同 | 电子签平台；小单至少邮件往来最终版 PDF 并让对方回复确认 |
| 设计、小额外包 | 微信或邮件确认最终版，加付款记录 |
| NDA | 电子签平台或 PDF 扫描件 |
| 用户协议、隐私政策 | 在线同意 + 服务端记录 |
| 变更单、验收确认 | 微信或邮件书面确认 |

常见的电子签平台有法大大、e 签宝、上上签、腾讯电子签等。选的时候看几点：能否对个人和企业做实名认证；签署时是否有短信验证码等意愿认证；签署完成后能否下载带数字签名的 PDF 和签署证据报告；是否支持「指定条款单独确认」（对第 1 章的格式条款提示有用）；收费方式是否适合你的签署量。价格和功能变化快，以平台官网为准。

### 用电子签平台时的几个细节

- **主体要对**。跟公司签，签署方要是公司的企业认证账号并加盖电子公章，而不是对方某个员工的个人账号。跟个体户签，确认签署人就是营业执照上的经营者
- **签署顺序**。一般由你先发起、对方签完你再签。发起前把合同文本定稿，签署过程中不要再改
- **下载留档**。签完立刻下载合同 PDF 和签署证据报告存到自己的存储里，不要只依赖平台账户。平台可能停止服务、账户可能到期
- **在合同里约定电子签效力**。加一句「双方同意以电子签名方式签署本合同，电子签名与手写签名、盖章具有同等法律效力」，呼应《电子签名法》第三条的「约定使用」

## 证据：法院怎么看电子数据

### 电子数据包括什么

最高人民法院《关于民事诉讼证据的若干规定》（2019 年修正，下称「证据规定」）第十四条列举了电子数据的范围：

1. 网页、博客、微博客等网络平台发布的信息
2. 手机短信、电子邮件、即时通信、通讯群组等网络应用服务的通信信息
3. 用户注册信息、身份认证信息、电子交易记录、通信记录、登录日志等信息
4. 文档、图片、音频、视频、数字证书、计算机程序等电子文件
5. 其他以数字化形式存储、处理、传输的能够证明案件事实的信息

微信聊天记录属于第 2 项，你系统里的同意记录、登录日志属于第 3 项，交付的代码和文档属于第 4 项。

### 要提供原件

证据规定第十五条第二款：当事人以电子数据作为证据的，应当提供原件。电子数据的制作者制作的与原件一致的副本，或者直接来源于电子数据的打印件或其他可以显示、识别的输出介质，视为电子数据的原件。

实务上，这意味着聊天记录截图打印出来可以作为证据提交，但对方质疑时，你要能拿出**存储原始数据的手机或电脑**当庭展示。所以：**聊天记录不要删，换手机要迁移，旧手机别急着卖**。

### 真实性怎么判断

证据规定第九十三条列举了法院判断电子数据真实性时考虑的因素，包括系统软硬件环境是否完整可靠、是否正常运行、是否有防止出错的监测核查手段、数据是否被完整地保存传输提取、是否在正常往来活动中形成和存储、保存提取的主体是否适当等。

第九十四条更实用，它列出了法院**可以确认真实性**的情形（有足以反驳的相反证据的除外）：

1. 由当事人提交或者保管的**于己不利**的电子数据
2. 由记录和保存电子数据的**中立第三方平台**提供或者确认的
3. 在**正常业务活动中形成**的
4. 以**档案管理方式**保管的
5. 以当事人**约定的方式**保存、传输、提取的

同条第二款：电子数据的内容**经公证机关公证**的，人民法院应当确认其真实性，但有相反证据足以推翻的除外。

把这一条翻译成一人公司的操作：

| 第九十四条的情形 | 你能做的 |
|---|---|
| 中立第三方平台 | 用电子签平台签合同；用邮箱服务而不是自建邮件服务器发重要通知 |
| 正常业务活动中形成 | 用平时就在用的微信、邮件、工单系统沟通，而不是纠纷发生后临时补记录 |
| 档案管理方式保管 | 合同、确认、交付、发票、付款按项目归档（下面有目录结构） |
| 约定的方式 | 合同里约定「双方确认以微信、电子邮件作为本合同项下的书面通知方式」 |
| 公证 | 金额较大、对方可能否认时，对关键聊天记录、网页做公证 |

### 时间戳和区块链存证

最高人民法院《关于互联网法院审理案件若干问题的规定》（法释〔2018〕16 号）第十一条规定：当事人提交的电子数据，通过电子签名、可信时间戳、哈希值校验、区块链等证据收集、固定和防篡改的技术手段或者通过电子取证存证平台认证，能够证明其真实性的，互联网法院应当确认。

这条规定针对的是互联网法院，但它反映的审查思路在其他法院也有参考意义。对开发者来说，这些技术手段一点都不陌生：

- **哈希值**：对合同 PDF、交付的代码包计算 SHA-256，写进交付确认邮件。日后对方说「你交的不是这个版本」，哈希值对得上就说明文件没改过
- **可信时间戳**：由第三方时间戳服务机构对文件哈希签发时间戳，证明「这个文件在某个时间点已经存在」。对证明代码、设计稿的创作时间有用（比如著作权纠纷中证明谁先完成）
- **区块链存证**：一些电子签平台、存证平台提供，原理也是把哈希上链

```bash
# 交付时计算哈希，写进交付邮件
git archive --format=tar.gz -o delivery-v1.0.tar.gz v1.0
shasum -a 256 delivery-v1.0.tar.gz
# 输出的哈希值连同 Git 标签名、提交哈希一起写进交付确认邮件
git rev-parse v1.0
```

Git 本身就是一个很好的证据系统：每个提交有哈希、有时间、有作者，历史不可悄悄改写（强制推送会留下痕迹）。交付代码时推送到客户的仓库，客户仓库里的提交记录就是「中立」程度更高的证据。

## 微信聊天记录：最常见也最容易出问题的证据

一人公司的大部分业务沟通在微信上。法院普遍接受微信聊天记录作为证据，但要过几道坎：

### 证明「对方是谁」

微信昵称可以随便改，头像可以随便换。法院首先会问：你怎么证明这个微信号就是被告本人？

- **一开始就备注真实身份**。加好友时备注「XX 餐饮 王经理 138xxxx」，并在聊天里让对方发一次名片、营业执照照片或者让对方确认身份
- **截图包含微信号**。保存证据时，先截对方的个人资料页（显示微信号），再截聊天记录
- **关联其他证据**。对方通过这个微信号向你转过账（转账记录会显示实名信息的部分内容），或者合同上留的联系方式就是这个微信号对应的手机号

### 保存完整，不要断章

```text
保存微信聊天证据的步骤：
1. 在原始手机上打开对话，先截对方的个人资料页，显示微信号
2. 从对话中与本事项相关的第一条消息开始，按时间顺序连续截图，不跳过、
   不裁剪；截图要能看到消息的日期时间
3. 语音消息转成文字后截图，并保留原始语音
4. 转账、文件、图片：点开后截图，文件另存原件
5. 对整个过程录屏：从打开微信、进入对方资料页、进入对话、逐条翻阅，一次
   录完，可以作为截图的补强
6. 在电脑端备份聊天记录；原始手机妥善保管，不删除对话
7. 金额较大、预计对方会否认的，在起诉前就关键记录办理公证或者使用取证
   存证平台
```

第 2 步「不裁剪」很重要。只截对自己有利的几句，对方拿出完整记录时，你的可信度就没了。

### 在聊天里「做证据」

平时沟通时有意识地让关键信息形成文字：

```text
反例：
对方：（语音 58 秒）
你：好的

改法：
对方：（语音 58 秒）
你：好的王经理，我确认一下：第二阶段验收通过，第三阶段款 X 元您这周五前
    付，第三阶段需求按 11 月 20 日那版文档做，对吧？
对方：对
```

这种「确认式复述」对方几乎不会反感，而一句「对」把整个约定固定了下来。验收、付款承诺、需求变更、对方的要求，都值得这样复述一遍。

## 你的系统日志也是证据

对 SaaS 来说，最有力的证据往往在你自己的系统里：

| 争议 | 系统里的证据 |
|---|---|
| 「我没同意过这个协议」 | 同意记录表：用户、版本、时间、渠道（第 3 章） |
| 「你们的系统把我的数据弄丢了」 | 数据变更流水：哪个账号、什么时间、改了哪张表哪一行 |
| 「我根本没用过」 | 登录记录、操作日志 |
| 「你们没提醒我要到期」 | 到期提醒短信的发送记录 |
| 「你们后台的人动了我的数据」 | 管理后台的操作日志 |

hatch-counter 已经有不少这样的记录：账本表的每一处改动由触发器记进变更流水，后台的停用、删店、续期、退款都进操作日志，到期提醒在到期前 7 天、1 天、当天发短信并有任务记录。

这些记录是在**正常业务活动中形成**的，符合第九十四条第（三）项。但要注意两点：

1. **保存期限要覆盖诉讼时效**。合同纠纷的诉讼时效一般是三年（《民法典》第一百八十八条，第 8 章细讲）。hatch-counter 的变更流水 90 天后压成按月计数，对「谁在什么时候改了哪一行」这类争议，90 天后就查不到明细了。是否延长、对哪些表延长，要在存储成本、个人信息最小保存期限和举证需要之间权衡；至少对账号同意记录、计费记录、后台操作日志，保存期限应当覆盖合同期限加诉讼时效
2. **日志的可信度来自系统的可靠性**。第九十三条看的是系统环境是否可靠、是否有防篡改手段。日志表只追加、业务角色没有更新和删除权限、定期把日志的哈希写进一个外部存储，这些做法都能提高可信度

## 一人公司的合同档案

第九十四条第（四）项说「以档案管理方式保管的」可以确认真实性。一人公司不需要档案室，但需要一个固定的结构：

```text
contracts/
├── customers/
│   └── 2026-11-dongfang-chuancai/          # 年月-客户简称
│       ├── 00-info.md                       # 主体信息、联系人、微信号、合同要点摘要
│       ├── 01-service-agreement-signed.pdf  # 签署版
│       ├── 01-service-agreement-evidence.pdf# 电子签证据报告
│       ├── 02-orders/                       # 每张订单
│       ├── 03-notices/                      # 发出和收到的通知（含快递单号）
│       ├── 04-chat-export/                  # 关键聊天记录导出、截图、录屏
│       └── 05-payments/                     # 收款凭证、发票
├── vendors/                                 # 你发包的项目，结构同上
└── templates/                               # 你的合同模板，带版本号
```

`00-info.md` 里写一段「合同要点摘要」：到期日、续费方式、付款节点、责任上限、争议解决方式。一年后出了问题，你不用重读整份合同。

这个目录要有备份，而且备份不能只在一个地方。合同档案丢失，跟没签差不多。

## 本章要点

- 服务合同、外包合同、NDA、用户协议都可以电子签署；不能仅因电子形式否定效力
- 可靠的电子签名要满足专有、控制、签名改动可发现、内容改动可发现四个条件；PDF 上贴签名图片不是可靠的电子签名，但邮件往来仍可证明合同成立
- 重要合同用第三方电子签平台，签完立刻下载合同和证据报告自己留档
- 电子数据要能提供原件：聊天记录不删、换手机要迁移
- 法院可以确认真实性的情形：中立第三方平台、正常业务活动中形成、档案管理方式保管、约定方式、公证
- 交付时计算哈希写进确认邮件；代码推到客户仓库；Git 历史本身就是证据
- 微信证据要证明对方身份、完整连续不裁剪、录屏补强；平时用「确认式复述」把口头约定变成文字
- 系统日志是 SaaS 最有力的证据，保存期限要覆盖合同期限加诉讼时效，并做到只追加、可校验
- 合同按客户建档：签署版、证据报告、订单、通知、聊天导出、付款凭证放在一起

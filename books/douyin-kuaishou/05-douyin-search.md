# 抖音搜索与长期流量

推荐流量像潮水：来得快，三五天就退了。对在职做副业、每周只能更新两三条的人来说，只靠推荐意味着账号的流量永远取决于「最近一条」。搜索流量是另一种东西：用户带着问题来找答案，只要你的作品能回答这个问题、排得上，它就会在几个月甚至几年里持续带来播放和粉丝。

这一章讲抖音搜索的基本情况、怎么找有搜索需求的选题、怎么让作品被搜到，以及怎么衡量。快手也有搜索，原理类似，最后一节简要说明。

## 抖音搜索有多大

公开数据不多，而且大多比较旧：

- 2021 年，字节跳动方面公开表示抖音视频搜索月活用户超过 5.5 亿，日均视频搜索量突破 4 亿（媒体报道，2021 年）。这是能查到的最近一次官方披露的搜索规模，**之后没有找到新的官方数字**
- 抖音官方在 2025 年公开推荐算法原理时，把「搜索与推荐联动」列为防止信息茧房的措施之一，说明搜索在系统里是和推荐并列的一条主要分发路径

不需要精确数字也能确定一件事：大量用户已经把抖音当作「视频版搜索引擎」，搜菜谱、搜软件教程、搜「xx 怎么选」「xx 避坑」。知识、教程、测评、本地生活类内容，搜索流量的占比往往比泛娱乐内容高得多（行业经验）。

## 哪些内容适合做搜索

| 适合 | 不太适合 |
|---|---|
| 教程、步骤：「Excel 怎么做下拉菜单」 | 纯搞笑、段子 |
| 问题解答：「Mac 风扇一直响怎么办」 | 强时效的热点评论（热点过了就没人搜） |
| 对比、选择：「iPad 和 MacBook 学生选哪个」 | 情绪类、氛围感内容 |
| 推荐、清单：「程序员必装的 5 个插件」 | 只有自己粉丝关心的日常 |
| 测评、避坑：「这个家用 NAS 我用了一年」 | |
| 本地信息：「杭州周末带娃去哪」 | |

判断标准只有一个：**有没有人会在搜索框里打出一句话来找这条内容**。

## 找有搜索需求的选题

### 工具

| 工具 | 是什么 | 用来做什么 |
|---|---|---|
| 抖音搜索框下拉联想 | 输入一个词时自动补全的候选词 | 最直接地看到用户真实在搜什么 |
| 搜索结果页的「相关搜索」「大家都在搜」 | 搜索结果页附近展示的相关词（位置以实际界面为准） | 扩展同一需求下的其他说法 |
| 巨量算数（巨量引擎旗下的官方数据工具） | 可以查关键词的热度趋势、关联词、人群画像 | 比较不同说法的热度，判断季节性 |
| 抖音热点宝 | 抖音官方的热点工具，看热榜和上升热点 | 找有时效性的搜索需求 |
| 创作者中心里的创作灵感 / 搜索热词类功能 | 部分版本的创作者中心会展示用户搜索多、但相关内容少的词（以实际界面为准） | 找「需求大、供给少」的词 |

巨量算数和热点宝的具体指标定义、可查范围以官方页面说明为准。

### 五步做一张关键词表

```mermaid
flowchart LR
  A["写 5–10 个种子词：你的领域里最核心的名词"] --> B["在搜索框逐个输入，记下所有下拉联想词"]
  B --> C["点进搜索结果，看前 10 条作品的质量和时间"]
  C --> D["用巨量算数比较热度"]
  D --> E["标注：需求大小 × 现有内容质量 → 选题优先级"]
```

1. **写种子词**：比如做「程序员效率」赛道，种子词可以是 Git、VS Code、Mac、Linux 命令、正则表达式
2. **收集联想词**：在搜索框输入「Git」，下拉会出现「git 撤销 commit」「git 回退版本」「git 冲突怎么解决」……把它们都记下来。再输入「Git 怎么」「Git 为什么」，会出现更多问题型的词
3. **看搜索结果**：对每个候选词搜一下，看排在前面的作品：
   - 有没有专门回答这个问题的作品？
   - 它们发布多久了？质量如何？是不是答非所问？
4. **比较热度**：在巨量算数里比较同一需求的不同说法（比如「git 撤销提交」和「git 回退」哪个搜得多），选热度高的说法作为标题主词
5. **标优先级**：需求大、但现有作品质量差或已经很旧的词，优先做

### 关键词表模板

| 关键词 | 搜索意图 | 热度（巨量算数相对值） | 现有前 10 条质量 | 优先级 | 计划作品 |
|---|---|---|---|---|---|
| git 撤销 commit | 解决问题 | 高 | 多为两三年前的录屏，不清晰 | A | 3 种场景 3 个命令 |
| git 冲突怎么解决 | 解决问题 | 中 | 有几条不错的 | B | 用动画讲原理 + 实操 |
| vscode 好用的插件 | 推荐清单 | 高 | 很多，但同质化 | C | 只讲「程序员写文档」场景的插件 |

表中热度和质量是示例填法。

## 让作品被搜到

### 关键词要出现在哪里

平台没有公开搜索排序的具体因素。下面是行业里普遍采用的做法，背后的逻辑是让系统能确定「这条作品回答的就是这个问题」：

| 位置 | 做法 | 说明 |
|---|---|---|
| 作品描述第一句 | 包含目标关键词的完整说法 | 最直接的文本信号 |
| 封面大字 | 包含关键词或问题 | 在搜索结果页里，用户靠封面决定点哪个 |
| 口播 | 开头就说出这个问题 | 行业经验认为平台会识别语音内容；对用户来说，第一句确认「这就是我要找的」也最重要 |
| 字幕 | 口播的关键词以字幕呈现 | 同上，平台可能识别画面文字（行业经验） |
| 话题 | 加一个和关键词一致的话题 | 辅助信号 |
| 合集名称 | 包含主题词 | 合集页也能被搜到 |
| 置顶评论 | 补充步骤要点，自然地包含关键词 | 评论区内容也可能被搜索系统使用（行业经验） |

口播和字幕被识别、评论被纳入搜索，是行业里普遍的判断，**没有找到官方的明确说明**。即使这些判断不准，这些做法对用户体验也是有益的，没有副作用。

不要做的：在描述里堆十几个关键词、在画面角落放一串和内容无关的热门搜索词、在评论区刷关键词。这些做法既影响阅读，也可能被视为低质或操纵。

### 搜索型作品的结构

搜索进来的用户和推荐进来的用户心态不同：他们**有明确的问题，想尽快得到答案**。所以结构要变：

| 推荐型作品 | 搜索型作品 |
|---|---|
| 前 3 秒制造好奇、冲突 | 前 3 秒确认「这就是你要找的」，并给出答案的概要 |
| 答案可以留到后面揭晓 | 答案越早给越好，后面补细节和原因 |
| 情绪、节奏驱动 | 清晰、步骤、可以暂停跟着做 |
| 时效性内容也可以 | 尽量做「一年后还有效」的内容 |

一个搜索型口播的开头示例：

```text
【0–3 秒】字幕：git commit 写错了怎么撤销
口播：commit 提交错了想撤销，分三种情况，用三个不同的命令，我一个个说。
【3–15 秒】第一种：还没 push，只想改提交信息。用 git commit --amend……
```

对比推荐型的开头「你是不是也遇到过这种尴尬」，搜索进来的人会直接划走去看下一条结果。

两种需求可以兼顾：开头一句话同时包含问题（给搜索）和一个反常识的点（给推荐），比如「commit 写错了别急着 reset，90% 的情况一个命令就够」。数字要是真的，不要为了钩子编造比例。

### 时效和更新

- **做常青内容**：软件教程在软件大版本更新后会过时，标题里可以写清楚版本（如「macOS 26」），过时后再做新版
- **老作品不用删**：搜索流量可能还在持续，在置顶评论里补充「新版本做法见合集第 x 集」
- **一个问题可以做多次**：同一个关键词，一年后做一条更好的新版，是正常的内容迭代

## 看后搜和搜索词提示

抖音的作品页、评论区里，有时会出现可点击的搜索词提示（例如作品下方的「相关搜索」、评论区里被高亮的词，具体形式以实际界面为准）。用户点击后会跳到对应的搜索结果。这是平台把推荐流量引向搜索的产品设计，对创作者的含义是：

- 你在推荐页火了的作品，可能带动相关关键词的搜索，你的其他相关作品也可能因此被搜到
- 你写在描述、评论里的词，有可能被系统选作提示词

这部分是平台的产品功能，展示哪些词由平台决定，创作者没有办法直接设置（商业投放除外，见《投流与数据分析》）。

## 怎么衡量搜索效果

1. **看流量来源里的搜索占比**：在创作者中心作品数据的流量来源里，记录每条作品的搜索流量占比（第 3 章的复盘表里有这一栏）
2. **看搜索词**：部分版本的作品分析会显示用户通过哪些搜索词找到这条作品（以实际界面为准）。如果搜索词和你的目标关键词不一致，说明你的表述和用户的说法有差距，调整下一条的用词
3. **看长尾**：发布 30 天、90 天后再回看一次播放量。搜索型作品的特征是 30 天后仍有稳定的日增播放
4. **手动搜索检查**：用另一个账号（或退出登录）搜你的目标关键词，看你的作品排在第几。搜索结果有个性化，这只能作为粗略参考

一个可以加到复盘表的字段：

| 作品 | 目标关键词 | 7 天搜索占比 | 30 天播放 | 90 天播放 | 主要搜索词（后台） |
|---|---|---|---|---|---|
| Git 撤销 commit | git 撤销 commit | 18% | 2.1 万 | 3.4 万 | git 撤销提交、git 撤回 |

示例数字只用于说明怎么填。

## 快手搜索

快手同样有搜索功能，用户也会搜教程、商品、本地信息。快手的差异在于：

- 快手用户的搜索习惯整体上不如抖音强（行业经验），搜索更多和**找人**（搜某个主播）、**找商品**相关
- 快手的双列发现页本身就带有「挑选」的属性，用户会根据封面选择点哪个，封面的信息量更重要
- 上面讲的关键词方法在快手同样适用：用快手搜索框的联想词找需求，把关键词写进描述、封面和口播

## 检查清单

**选题阶段**

- [ ] 这个选题有人会主动搜吗？在搜索框里输入，有下拉联想词吗？
- [ ] 现有前 10 条结果质量如何？我能做得更好、更新、更清楚吗？
- [ ] 选了热度最高的那种说法作为主关键词吗？

**制作阶段**

- [ ] 第一句口播就说出问题，并给出答案概要
- [ ] 关键词出现在字幕、封面大字里
- [ ] 内容一年后还成立，或者在标题里写了版本

**发布阶段**

- [ ] 描述第一句包含完整关键词
- [ ] 加了一个与关键词一致的话题
- [ ] 加入了对应主题的合集
- [ ] 发布后置顶一条补充要点的评论

**复盘阶段**

- [ ] 记录 7 天搜索占比和后台显示的搜索词
- [ ] 30 天、90 天各回看一次播放量

## 本章要点

- 推荐流量来得快去得快，搜索流量慢但持久，是副业创作者最值得经营的长期资产
- 抖音最近一次官方披露的搜索规模是 2021 年的「视频搜索月活超 5.5 亿」，之后没有新的官方数字
- 用搜索框联想词、相关搜索、巨量算数、热点宝和创作者中心的搜索热词功能做关键词表，优先做需求大、现有内容差的词
- 关键词写进描述第一句、封面、口播开头、字幕、话题和合集名；口播字幕被识别、评论被搜索是行业经验，不是官方说明
- 搜索型作品要先确认问题、尽早给答案，做一年后仍然有效的内容
- 用流量来源里的搜索占比、后台搜索词和 30 / 90 天长尾播放衡量搜索效果

# 验证需求：预售与小范围试讲

做知识产品最贵的错误，是花三个月录完一门课，上线后发现没人买。开发者对这种错误应该很熟悉：没有用户验证就写完整个系统。知识产品的解法也一样，**先用最小的成本证明有人愿意付钱，再投入生产**。

这一章讲三件事：怎么在动手之前判断一个选题有没有需求；怎么用预售和试讲拿到「真金白银」的验证；怎么定判断标准和止损线。

## 「有需求」的三个层次

很多人把「有人点赞」「有人说想学」当作需求的证据，但这几种信号的可信度差别很大：

| 信号 | 例子 | 可信度 |
|---|---|---|
| 注意力 | 相关视频播放高、文章收藏多 | 低：看免费内容和付钱是两回事 |
| 表态 | 评论区说「出课吧」「想学」、问卷勾选「愿意购买」 | 中低：说想要不需要成本 |
| 行动 | 留联系方式进等候名单、付定金、预售下单 | 高：付出了成本 |
| 付全款 | 预售付全款、试讲付费 | 最高 |

验证需求的目标，就是**尽快从前两层走到后两层**。一百个「想学」不如十个付了定金的人。

## 动手前的桌面调研

在做预售之前，先花一两个晚上做桌面调研，排除明显不成立的选题。

### 看三类数据

**1. 你自己的内容数据**

翻一遍过去发过的内容，找出这几类：

- 收藏率明显高于平均的（收藏说明「以后要用」，比点赞更接近学习需求）
- 评论区反复出现同类追问的（「这个具体怎么配置」「有没有完整教程」）
- 私信里被问过三次以上的问题

这些是最可靠的选题来源。用数据倒推选题的通用方法见《选题与爆款结构》。

**2. 同类产品**

去小报童、知识星球、小鹅通店铺、B 站课堂、各平台的课程橱窗看同主题的付费产品：

- 有没有人在卖？**有人卖是好事**，说明有人付钱；完全没人卖，要么是蓝海，更可能是没需求
- 卖多少钱？大致销量（很多平台显示购买人数或订阅数）？
- 看差评和评论：买家抱怨什么？「太浅」「过时」「只讲概念不带做」，这些抱怨就是你的切入点

**3. 搜索和问答**

在知乎、小红书、B 站、即刻、V2EX 搜相关问题，看有多少人在问、问题有多具体、最近还有没有人问。技术主题过时很快，**半年前的热门问题现在可能已经被工具更新解决了**。

### 一页需求笔记

调研结束，写一页笔记：

```markdown
## 选题：用 AI 编程工具独立做出一个小工具

### 证据
- 我的 B 站「Cursor 从零做浏览器插件」收藏率 8%，频道平均 3%
- 评论区 40+ 条在问「后端怎么部署」「数据库怎么选」
- 私信被问「能不能带着做一个」至少 6 次
- 小报童同类专栏 3 个，最高订阅数显示 2000+，价格 49–99 元
- 同类训练营差评集中在「只讲提示词，不讲上线」「群里没人答疑」

### 我的切入点
- 讲到上线为止，不只是写代码
- 每份作业都有人看

### 还不确定的
- 读者愿意为训练营付多少钱
- 我每周能不能稳定拿出 10 小时
```

「还不确定的」那一栏，就是下一步预售要回答的问题。

## 预售：让人先付钱

预售是在产品没做完、甚至没开始做的时候，**先公开卖**。卖得动就做，卖不动就退款、换选题。

### 预售前要准备什么

不需要做完产品，但需要准备好下面这些：

| 要准备的 | 说明 |
|---|---|
| 一句话承诺 | 来自产品设计画布（第 1 章），读者买到什么结果 |
| 大纲 | 至少到「每周 / 每讲讲什么」的粒度，见第 3 章 |
| 交付方式和时间 | 什么时候开课、怎么上课、多久更新完 |
| 价格和预售优惠 | 预售价通常低于正式价，作为早期支持者的回报 |
| 退款规则 | **必须写清楚**，尤其是「人数不够不开课全额退」 |
| 收款方式 | 小报童 / 知识星球 / 小鹅通等平台，或企业微信收款，见第 6 章 |
| 一页销售页 | 简版即可，结构见第 7 章 |

### 预售的写法要点

预售最大的风险是**承诺了做不到的东西**。几条原则：

- **写清楚「目前做到哪一步」**：「大纲已定，第一讲已写完，其余按每周两讲的节奏更新，预计 X 月 X 日前全部更新完」
- **写清楚不成立的情况怎么办**：「X 月 X 日前不满 20 人，不开营，全额原路退款」
- **预售价要真实**：预售价、正式价都要是你真的会执行的价格。虚构一个从来没卖过的「原价」划掉，属于价格欺诈（见《定价与商业模式》第 3 章）
- **不要用「最后 X 个名额」制造假稀缺**：名额有限就写真实的上限和理由（「每期点评作业的人数有限，上限 30 人」）

一个预售公告的示例：

```text
【预售】四周带你用 AI 编程工具做出并上线一个小工具

适合：有一点编程基础、会用 AI 聊天但还没用它做出过完整项目的人
结营时你会有：一个上线可访问的小工具 + 代码仓库 + 一份部署笔记

形式：每周一次直播（可回放）+ 每周一份作业，作业我逐份看并写点评
时间：12 月 1 日开营，共四周
预售价：499 元（正式开营后 699 元）

开不开营：11 月 25 日前满 15 人开营；不满 15 人，全额原路退款
退款：开营后第一周结束前，不满意可全额退款，不问原因

目前进度：大纲已完成（见下方），第一周内容已备好，其余三周开营后按周准备
```

### 预售在哪里发

- **你自己的私域**最好：读者群、企业微信好友、公众号。这里的人最认识你，转化最高（私域的搭建见《国内私域与内容平台》第 6 章）
- 公域平台：发一条讲清楚选题来由的内容，引导感兴趣的人到私域或预售链接。**注意各平台的导流规则**，不要在内容里直接放微信号和站外链接（见《国内私域与内容平台》第 9 章）
- 不建议第一次预售就投流。投流适合验证过的产品放量，验证阶段花钱买来的数据反而会干扰判断（投流见《投流与数据分析》）

## 小范围试讲

预售回答的是「有没有人买」，试讲回答的是「**讲出来有没有用**」。两者可以同时做。

### 三种试讲

| 形式 | 做法 | 适合 |
|---|---|---|
| 免费直播试讲 | 拿课程中的一讲做一次公开直播 | 测吸引力，收集问题 |
| 低价试讲班 | 5–15 人，收少量费用，讲两三次 | 测内容效果，产出首批案例 |
| 一对一试讲 | 按你的大纲带一两个人走一遍 | 测路径是否走得通 |

**低价试讲班**最值得做：收一点钱（比如正式价的一到三成），能筛掉不认真的人；人少，你能看清每个人卡在哪里。

### 试讲时观察什么

带着问题去讲，每次讲完记录：

```markdown
## 试讲记录：第 N 次

- 日期 / 人数 / 时长：
- 讲到哪一节时，提问最集中？问的是什么？
- 哪一步有人跟不上？卡在什么地方？（环境配置？概念？）
- 作业提交了几份？没交的人是什么原因？
- 有没有人说「这个我早就知道」？（内容太浅的信号）
- 有没有人中途离开或沉默？（节奏或难度问题）
- 我讲的时候，哪里自己也讲不顺？
- 下一次要改的三件事：
```

开发者讲技术课最常见的问题是**低估了环境配置的难度**。你觉得「装个 Node 配个 API Key」是一分钟的事，一半学员会卡在这里一整晚。试讲最大的价值，就是在正式开课前把这些坑找出来，写进课前准备清单。

### 试讲学员是最好的种子

试讲结束，对每一位学员：

1. 发一份简短的反馈问卷（3–5 个问题，见第 8 章）
2. 征得同意后，把他们的成果（作品截图、前后对比）作为正式课的案例。**必须本人同意，案例必须真实**
3. 给他们正式课的优惠或免费名额，他们往往会成为第一批推荐人

## 判断标准和止损线

预售和试讲最怕的是结果模棱两可，于是一直犹豫。**在开始之前就把判断标准写下来**：

| 结果 | 判断 | 动作 |
|---|---|---|
| 预售达到目标人数，试讲反馈好 | 成立 | 按计划生产和交付 |
| 预售达到目标的一半左右，试讲反馈好 | 需求存在但规模小 | 缩小规模开营，或换形态（做成小册 / 小班） |
| 预售远低于目标，咨询的人多但不下单 | 价格或承诺有问题 | 访谈没下单的人，调整价格或结果承诺后再试一次 |
| 预售远低于目标，也没人问 | 选题不成立或触达不够 | 全额退款，回到需求笔记 |
| 预售很好，试讲发现内容走不通 | 承诺过大 | 立即修改承诺并告知已付款者，提供无条件退款 |

目标人数怎么定：用你的私域规模估算。比如你的读者群和企业微信好友加起来 1500 人，预售目标定在几十人是现实的；定 300 人就是在赌。转化比例因人而异，**用你上一次推广的实际数据来定**，没有就保守估计，宁可定低一点。

止损线也要写下来，例如：

- 最多验证两轮，两轮都没达到一半目标，换选题
- 验证期最多投入四周，不录完整课程、不做设计精美的物料
- 已收的预售款，不成立时**全额、原路、按承诺时间**退完

## 访谈没有下单的人

预售结束后，最有价值的信息往往来自那些**问过但没买的人**。挑 5–10 位单独聊，语气是请教，不是追单：

```text
你好，之前你问过训练营的事，最后没有报名，完全没关系。
我在复盘这次的设计，想请教一下：是哪方面让你决定先不报？
时间、价格、内容、还是别的？你说得越直接对我帮助越大，谢谢。
```

常见的回答和对应的调整：

| 回答 | 可能的调整 |
|---|---|
| 「最近太忙，怕跟不上」 | 增加回放、延长有效期，或做成自学版 |
| 「不确定我的基础够不够」 | 写清楚入学门槛，提供课前自测题 |
| 「有点贵」 | 先别降价，看是不是价值没讲清；或拆出一个更轻的版本 |
| 「不知道学完能做什么」 | 结果承诺不够具体，补充示例作品 |
| 「看了大纲觉得我都会」 | 目标人群定错了，或内容太浅 |

## 本章要点

- 需求信号分四层：注意力、表态、行动、付全款；验证就是尽快拿到「付了钱」的证据
- 先做桌面调研：自己内容的收藏和追问、同类产品的价格和差评、搜索和问答，写成一页需求笔记
- 预售前准备承诺、大纲、交付时间、价格、退款规则和简版销售页；写清进度和「不成立就全额退」
- 低价小班试讲最值得做：测内容能不能走通，找到环境配置这类隐藏的坑，产出首批真实案例
- 开始前写下判断标准和止损线；结果模糊时按表行动，不要一直犹豫
- 访谈问过但没买的人，他们的理由决定下一轮怎么改

# 交付与口碑

知识付费行业口碑不好，一个重要原因是很多产品**把力气都花在了卖上，交付敷衍了事**。反过来看，这也是个人做知识产品的机会：只要你把交付做扎实，就能在一片「卖完就不管」里显得与众不同。

对一个没有投放预算的在职开发者来说，口碑几乎是唯一可持续的获客方式：第一期学员的作品和推荐，决定了第二期能不能招满。这一章讲怎么把交付做成一套可检查的流程，怎么收集反馈和案例，怎么让转介绍和复购自然发生。

## 交付的三个层次

| 层次 | 读者感受 | 做到什么 |
|---|---|---|
| 兑现 | 「说好的都给了」 | 销售页上写的每一项服务都按时做到 |
| 有效 | 「我真的学会了 / 做到了」 | 学员拿到了课程承诺的结果 |
| 超出预期 | 「比我想的好」 | 在承诺之外，多给一点用心的东西 |

第一层是底线，**做不到就是违约**。很多纠纷来自「直播说好每周两次，后来变成一次」「说好作业逐份点评，后来只点评了一部分」。第二层是口碑的来源。第三层锦上添花，但不能用它来弥补前两层的缺失。

## 交付检查清单

把销售页上的每一个承诺，变成一张交付检查清单，每期开营前打印出来（或做成任务列表），逐项打勾。

### 训练营交付检查清单

```markdown
## 交付检查：第 X 期

### 开营前
- [ ] 每位学员 24 小时内收到欢迎消息
- [ ] 课前准备材料已发送，并确认链接都能打开
- [ ] 所有学员都完成了环境配置（未完成的已单独跟进）
- [ ] 分组和助教安排完成
- [ ] 直播链接、回放位置测试通过

### 每周（第 1–4 周，每周复制一份）
- [ ] 周一按时发布学习内容和作业
- [ ] 直播按时开始，回放 24 小时内上传
- [ ] 群内问题在承诺时效内回复
- [ ] 作业在承诺时间内全部点评完
- [ ] 未交作业的学员已私聊跟进
- [ ] 本周常见问题已整理发布

### 结营
- [ ] 结营展示会举办，所有作品已展示
- [ ] 每位学员收到结营反馈（个人作品点评 + 下一步建议）
- [ ] 反馈问卷已发送
- [ ] 案例授权已征询
- [ ] 回放和课件的有效期已告知

### 结营后
- [ ] 一周内收集问卷并汇总
- [ ] 承诺的有效期内，回放和课件可正常访问
- [ ] 复盘完成，下一期改进项已记录
```

### 录播课和社群的交付检查

录播课和社群没有明确的「期」，但同样有承诺要兑现：

| 产品 | 定期检查 |
|---|---|
| 录播课 | 每月检查所有视频和链接能打开；评论区和答疑在承诺时效内回复；工具版本更新导致的内容过时，及时补充说明或补录 |
| 小册 / 专栏 | 承诺的更新频率按时完成；读者留言回复 |
| 付费社群 | 按内容日历更新（第 4 章）；提问在承诺时效内回复；每月看一次活跃和退款数据 |
| 模板 / 工具包 | 购买后的下载链接持续有效；工具更新后模板仍可用 |

**录播课的内容过时**是技术类课程的特有问题。AI 编程工具几个月就会有一次大的界面或功能变化，学员看到的界面和课程里不一样就会困惑，进而觉得「课程过时了」。几个做法：

- 在课程首页维护一个「更新日志」，写明每次更新了哪几讲
- 工具变化不大时，在相关章节开头加一段文字说明「新版本中这个按钮移到了……」
- 变化大到影响学习时，补录这一讲
- 在销售页写明课程基于哪个版本录制、内容更新的方式

## 结营：最重要的一天

结营是学员对整个训练营印象最深的时刻，也是口碑、案例、转介绍的集中产出点。

### 结营展示会

每个学员用 3–5 分钟展示自己的作品：做了什么、遇到了什么困难、怎么解决的。好处是：

- 学员看到自己和同伴的成果，成就感很强
- 你可以现场看到哪些学员做得特别好，适合邀请做案例或下一期助教
- 展示的录屏（经同意）是下一期销售页最好的素材

人多的话，可以只请自愿的学员展示，其他人在群里发作品截图。

### 结营反馈

给每位学员发一段个人化的结营反馈，不需要很长，但要具体：

```text
恭喜你完成了四周的训练营！

你的作品「周报生成器」从第一周的命令行脚本，到现在有界面、能部署、
还加了导出功能，进步非常明显。你在第三周排查部署问题的那份说明写得很清楚，
这个习惯以后会帮你很多。

接下来的建议：
1. 找三位同事试用，收集他们的意见
2. 把环境变量和密钥的管理再整理一下（参考第 3.4 讲）
3. 如果想把它做成一个真正的产品，可以看看 ____

课程回放和课件在 12 个月内都可以继续看。有问题随时找我。
```

这段反馈的成本是每人 5–10 分钟，但它往往是学员最终评价这个训练营的决定性时刻。

## 收集反馈

### 反馈问卷

结营当天或之后一两天发问卷，问题不要多，5–7 个：

```markdown
1. 这个训练营你打几分？（1–10）
2. 你会向朋友推荐这个训练营吗？（1–10）
3. 对你最有帮助的是哪一部分？
4. 哪一部分你觉得可以去掉或者需要改进？
5. 训练营前后，你在 ____ 方面有什么变化？（具体一点）
6. 你还希望学什么？（下一步的产品方向）
7. 我们可以引用你的回答作为学员反馈吗？（可以，用全名 / 可以，匿名 / 不可以）
```

第 2 题就是常见的「净推荐值」问题。打 9–10 分的人是你潜在的推荐者，打 6 分以下的人要单独联系，问清楚哪里没做好。

第 7 题是**案例授权**。反馈要在宣传中使用，必须事先征得同意，并尊重他选择的署名方式。

### 看什么数据

每期交付结束后，记录这几个数字，看它们在几期之间的变化：

| 指标 | 怎么算 | 用来判断 |
|---|---|---|
| 完课率 | 完成结课项目的人数 ÷ 开营人数 | 课程难度和运营是否合适 |
| 退款率 | 退款人数 ÷ 报名人数 | 销售页和产品是否一致 |
| 满意度均分 | 问卷第 1 题的平均分 | 整体体验 |
| 推荐意愿 | 问卷第 2 题打 9–10 分的比例 | 口碑潜力 |
| 复购 / 升级率 | 购买下一级产品的人数 ÷ 完课人数 | 阶梯是否连得上 |
| 转介绍人数 | 下一期中由往期学员推荐来的人数 | 口碑是否真的转化成了生意 |

不要和别人的数字比，**和自己的上一期比**。哪个数字变差了，就去找对应的原因。

## 案例

案例是口碑的「证据」。一个具体、真实的学员案例，比十句「课程很好」更有说服力。

### 好案例的结构

```markdown
## 学员案例：____（经本人同意，署名方式：____）

### 之前
- 背景：（工作、经验）
- 遇到的问题：

### 在训练营中
- 做了什么项目：
- 遇到的最大困难和怎么解决的：

### 之后
- 作品：（链接或截图）
- 变化：（具体的、可验证的）

### 他自己的话
> （原话，不改写）
```

### 案例的红线

- **必须真实**，必须征得本人同意，本人要求撤下时及时撤下
- **不用收入作为案例的卖点**。「学员 A 学完接单赚了 5 万」这类案例，即使是真的，也会被读者理解为你在暗示「学了就能赚钱」，这触碰了教育培训广告不得保证效果的红线，也违反多个平台的规则
- 不要只挑最好的个例来暗示普遍效果。可以说「这是做得比较好的一位学员」，而不是让读者以为人人都能做到
- 涉及学员的工作单位、项目内容时，注意不要泄露他的工作秘密

## 转介绍

转介绍应该是「好交付的副产品」，而不是靠利益驱动出来的。

### 让推荐自然发生

- **给学员可以分享的东西**：结营证书（写明完成了什么项目，不夸大）、作品链接、结营展示的录屏
- **在合适的时机提**：在结营反馈里、在推荐意愿打 9–10 分的人回复之后，而不是每次都提
- **让推荐变容易**：给一个可以直接转发的简短介绍和链接

```text
谢谢你给了这么高的评价！如果身边有同事或朋友也想做类似的事，
可以把这个链接发给他：____
下一期 1 月中开营，通过你推荐来的朋友报名，你们两个都可以得到 ____。
```

### 推荐奖励

推荐奖励可以有，但要注意：

- 奖励**写清楚规则**：谁能拿、什么条件、什么时候发
- 推荐双方都有好处比只奖励推荐人更好，被推荐的人不会觉得自己被「卖」了
- 平台自带的分销功能（如小报童的分销）按平台规则执行
- **不要做多级分销**。「你推荐的人再推荐，你也能拿提成」这类多层级的返利结构，有涉嫌传销的法律风险，平台也普遍禁止
- 推荐人以个人身份在朋友圈推广你的课程并拿佣金，本质上是在做商业推广，相关的标注和合规要求见《自媒体与短剧合规财税》

## 复购

复购是阶梯（第 1 章）在交付之后的延续。学员买了主力品并且满意，自然会想知道「下一步学什么」。

| 已购 | 自然的下一步 |
|---|---|
| 小册 | 训练营（带着做） |
| 录播课 | 训练营或付费社群（持续交流） |
| 训练营 | 进阶训练营、付费社群、一对一陪跑 |
| 付费社群 | 续费；社群里专题训练营 |
| 一对一 | 按月顾问 |

几个原则：

- **复购的前提是上一次交付好**。交付没做好就推下一个产品，只会加速流失
- **老学员优先和优惠**：下一期或进阶课程先通知老学员，给老学员真实的优惠
- **问卷第 6 题（还希望学什么）**是下一个产品的需求来源，回到第 2 章验证它
- 不要在学员还没学完当前课程时推销下一个产品

## 差评和负面反馈

做久了一定会有差评。处理原则和第 9 章的客诉处理相通：

- **先看是不是真的问题**。如果是交付没做到位，公开承认并说明改进措施
- **不删除、不屏蔽真实的负面评价**（平台允许的话可以回复）。读者看到一个有好评也有中性评价、差评得到认真回复的产品，比只有五星好评的产品更可信
- **不刷好评**、不让朋友冒充学员写评价、不用返现换好评。这些都违反平台规则和反不正当竞争、消费者保护方面的规定

一个公开回复差评的示例：

```text
谢谢你的直接反馈。第三周的作业点评确实比承诺的晚了两天，这是我的问题，
当时工作上临时有上线，没有安排好。
从下一期开始，我增加了一位助教，确保点评在周日前全部完成。
你的退款已经按规则办理；如果愿意，下一期欢迎免费回来旁听第三周。
```

## 本章要点

- 交付分三层：兑现、有效、超出预期；兑现是底线，做不到就是违约
- 把销售页上的每个承诺变成交付检查清单，每期逐项打勾；录播课定期检查链接和内容是否过时
- 结营是口碑的集中产出点：展示会 + 每人一段具体的结营反馈
- 问卷 5–7 题，包含推荐意愿和案例授权；每期记录完课率、退款率、推荐意愿、复购和转介绍，和自己的上一期比
- 案例必须真实、经同意，不用收入作卖点，不用个例暗示普遍效果
- 转介绍是好交付的副产品；奖励规则写清楚，双方都有好处，不做多级分销
- 复购建立在上一次交付之上；真实的负面评价认真回复，不删不刷

# 企业微信与客户群

国内做私域，容器几乎只有微信生态一个选择。问题是用个人微信还是企业微信。这一章的结论是：**To B 产品用企业微信，有主体就认证**。下面讲为什么、怎么开、有哪些硬性上限、渠道怎么追踪、客户群怎么建，以及开发者能用的几个接口。

社群本身怎么运营（规则、话题、活跃）放在第 7 章；种子用户群的基本原则见《获客与增长》第 4 章。

## 个人微信还是企业微信

| | 个人微信 | 企业微信 |
|---|---|---|
| 客户看到的身份 | 一个普通人 | 带企业名称的工作身份 |
| 好友 / 客户上限 | 公开报道称约 1 万（腾讯客服答复，2023 年） | 单个成员外部联系人和客户合计最多 2 万；企业总量另有上限（见下文） |
| 欢迎语、标签、渠道追踪 | 只能手动 | 内置，可按渠道自动打标签 |
| 群发、朋友圈 | 手动；用外挂群发违规 | 官方群发和客户朋友圈，有频次上限 |
| 换人、离职 | 客户跟着号走 | 可以分配和继承客户 |
| 接口 | 没有官方接口，用外挂会封号 | 有官方 API |
| 风控 | 频繁加人、群发容易触发异常 | 规则明确，按官方功能用风险低 |
| 亲近感 | 高，朋友圈像真人 | 略低，部分人对「企业号」有戒心 |

一人公司的现实选择：

- **To C、个人品牌为主**：个人微信更自然，但要严格控制加人和群发频率，永远不用外挂
- **To B、要跟进成交和续费**：企业微信。标签、渠道追踪和接口能省下大量手工活，而且你未来如果招一个兼职客服，客户可以直接分配过去

也可以两者并用：个人微信只放已经很熟的客户和同行，企业微信作为所有新线索的入口。不要反过来，把新客户全加到个人微信，等量大了再迁移，那时候迁不动了。

## 开通和认证

### 没有主体能不能用

可以。个人可以直接创建一个企业微信组织（不认证），自己当管理员。但未认证有很硬的限制：

- **客户上限 100 人**，包括已删除的外部联系人和客户，全企业成员共享（来源：企业微信帮助中心「外部联系人/客户数量上限是多少」，2026-11 查阅）
- **客户群只能邀请 200 位客户或外部联系人**（来源：企业微信「客户群」功能介绍页，2026-11 查阅）

100 个客户对验证阶段是够的。但一旦超过，就必须认证，而认证需要主体。所以**时间线要倒过来排**：预计私域客户会在几个月内超过 100 人时，提前把个体户或公司办下来（主体选择见《国内合规实务》第 1 章）。

### 认证

- **费用**：每次申请审核服务费 300 元，审核成败都不退；按成员规模另收费，1000 人以下的企业不涉及这部分（来源：企业微信帮助中心「认证费用与年审」，2026-11 查阅）
- **年审**：认证有效期一年，每年年审，费用与首次认证相同；过期后失去认证标识和更高的成员、客户上限（同上）
- **主体**：帮助中心列出的是企业、事业单位、社会团体等组织类型，没有明确写个体工商户。个体户能否认证企业微信，以认证页面实际可选项为准

### 认证后的客户上限

企业微信帮助中心对已认证企业写了两种情况（2026-11 查阅）：

- 管理后台**能看到「外部联系人规模」入口**的：认证后免费获得 2000 位外部联系人规模，全企业共享，超出部分按需购买
- **看不到这个入口**的：认证后初始客户上限 5 万，到上限后可以申请扩容

此外，**单个成员**外部联系人与客户合计不超过 2 万，且不支持扩容；企业总量满了，即使成员个人没满也加不了（同上）。

对一人公司，2000 的免费规模在相当长的时间里够用。真正要注意的是：**已删除的客户也占名额**（至少未认证时是这样），不要随手加、随手删。

## 渠道活码：知道每个人从哪来

企业微信最有价值的功能之一，是给不同渠道生成不同的「联系我」二维码，客户扫哪个码加进来，你就知道他来自哪里。

在管理后台（「客户联系」相关菜单，具体位置以当前后台为准）可以直接创建「联系我」二维码，并设置：

- 由哪个成员接待
- 加好友时是否需要验证（建议不需要，减少一步）
- 自动打上的标签
- 自动发送的欢迎语

一个渠道一个码，命名规则提前定好：

```text
命名：<平台>-<内容类型>-<年月>-<主题>
例：
oa-article-2611-breakeven     公众号 11 月保本线那篇文章
oa-menu                       公众号菜单「联系我们」
ch-video-2611                 视频号 11 月视频链接到的文章
site-footer                   官网页脚
offline-flyer-2611            线下传单
app-login-help                产品登录页「还没开通」那一步
referral-<客户简称>           老客户转介绍专用码
```

每个码自动打上同名标签。月底统计时，按标签数一下新增客户，就是每个渠道的真实转化，比任何「平台后台的阅读数」都更接近你要的结果。渠道评估的方法见《获客与增长》第 8 章。

### 用接口批量生成

如果渠道很多，或者想在自己的系统里管理这些码，可以用「配置客户联系『联系我』方式」接口。要点（来源：企业微信开发者中心文档，2026-11 查阅）：

- `POST https://qyapi.weixin.qq.com/cgi-bin/externalcontact/add_contact_way?access_token=...`
- `type` 1 为单人、2 为多人；`scene` 2 为二维码
- `state` 是企业自定义的渠道值，**不超过 30 个字符**，之后调用「获取客户详情」时会原样返回
- 返回的 `config_id` 要保存好，丢了会无法编辑或删除这个码
- 自建应用要配置到「客户联系 可调用接口的应用」里；使用成员需已激活、已实名、已配置客户联系功能

```typescript
// 给一个渠道生成「联系我」二维码；access_token 的获取和缓存略
type AddContactWayResult = {
  errcode: number;
  errmsg: string;
  config_id?: string;
  qr_code?: string;
};

export async function createChannelQr(
  accessToken: string,
  userId: string,
  state: string,
): Promise<AddContactWayResult> {
  if (state.length > 30) throw new Error("state 不能超过 30 个字符");
  const res = await fetch(
    `https://qyapi.weixin.qq.com/cgi-bin/externalcontact/add_contact_way?access_token=${accessToken}`,
    {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        type: 1, // 单人
        scene: 2, // 二维码
        user: [userId],
        skip_verify: true,
        state, // 例如 "oa-article-2611-breakeven"
        remark: state,
      }),
    },
  );
  const data = (await res.json()) as AddContactWayResult;
  if (data.errcode !== 0) throw new Error(`企业微信返回 ${data.errcode}: ${data.errmsg}`);
  // config_id 一定要存下来，丢了就没法再编辑或删除这个码
  return data;
}
```

一人公司早期用后台手动建十几个码就够了，接口是渠道多到手动管理不过来时再上的。

## 欢迎语和第一句话

客户扫码加进来的那一刻，是转化率最高的时候。欢迎语要做三件事：**说明你是谁、回应他为什么来、给出下一步**。按渠道设置不同的欢迎语：

```text
渠道：公众号保本线文章（标签 oa-article-2611-breakeven）

您好，我是掌柜眼的开发者，叫我小 X 就行。
文章里那张保本线计算表在这里：[文件]
填的时候哪一格不知道怎么填，直接问我。
如果想看看软件怎么自动算这笔账，回复「演示」，我约个时间给您远程演示 15 分钟。
```

```text
渠道：产品登录页「还没开通」（标签 app-login-help）

您好，我是掌柜眼的客服，也是开发者。
您是想给自己的店开通，还是店里的员工需要登录？
- 想开通：告诉我店名和大概几个人用，我帮您开一个 14 天的试用店
- 员工登录：请店主在「成员权限」里加上您的手机号就可以
```

反例：

```text
您好！欢迎关注掌柜眼！掌柜眼是一款功能强大的智能门店管理系统，
支持销量导入、库存管理、开支记账、经营分析等功能……
点击链接了解更多：xxx
```

问题：没有回应对方为什么来，一大段功能介绍没人看，没有一个具体的下一步。

## 客户标签和跟进记录

企业微信的客户详情里可以打标签、写备注。建议的标签体系不要太复杂：

| 标签组 | 标签 |
|---|---|
| 来源 | 渠道活码自动打，见上文 |
| 阶段 | 线索 / 已演示 / 试用中 / 已付费 / 流失 |
| 门店类型 | 快餐 / 正餐 / 面馆 / 茶饮 / 其他 |
| 门店数 | 1 家 / 2–3 家 / 4 家以上 |

阶段标签要**每次状态变化时手动改**。这是一个人做销售时最省事的「CRM」：月底按阶段标签筛一下，就知道漏斗每一层有多少人。成交流程本身（演示、报价、签单）见《销售与 To B 成交》。

但要记住第 1 章说的：企业微信里的数据不是你的。**付费客户的关键信息**（门店名、联系人、手机号、开通日期、到期日）要记在你自己的系统里。hatch-counter 的做法是开户只从管理后台来，客户和门店、订单、到期日都在自己的数据库里，企业微信只是沟通工具。

## 群发和客户朋友圈的上限

企业微信的群发和朋友圈都有频次上限，规则可以由管理员在一定范围内调整。官方页面的说法（2026-11 查阅）：

- **成员群发给客户**：每位客户每天可接收 1 条群发消息（企业创建的和成员自己创建的都算）
- **企业统一群发**：官方功能页写的是每位客户每月可收到企业的 4 条；开发者文档写的是每位客户 / 每个客户群每月最多可接收的条数为当月天数。两处说法不一致，以管理后台「群发规则」的实际设置为准
- **客户朋友圈**：每位客户的朋友圈每个自然日最多展示 3 条成员发表的内容

上限之外还有一个更重要的约束：**客户的耐心**。一人公司建议的节奏：

| 动作 | 频率 |
|---|---|
| 群发给全部客户 | 每月不超过 2 次，只发真正有用的（重要更新、停机通知、实用模板） |
| 群发给某个标签 | 按需，例如只给「试用中」的人发试用到期提醒 |
| 客户朋友圈 | 每周 2–3 条：经营方法、客户故事（经同意）、产品更新，少发硬广 |
| 单聊 | 按跟进计划，见第 10 章 |

## 客户群

客户群是企业微信里的外部群，可以拉客户进来。建不建、建几个，取决于你要它做什么：

| 群的用途 | 建议 |
|---|---|
| 付费客户服务群（所有客户一个群） | 适合早期，客户之间能互相解答，你发通知也方便 |
| 一店一群（客户的店主、店员 + 你） | 适合客单价高、需要深度服务的客户；群多了一个人管不过来 |
| 试用用户群 | 适合批量开试用时集中答疑，试用结束后解散或转入正式群 |
| 潜在客户群 / 行业交流群 | 运营成本高，没有足够内容支撑容易变成广告群，早期不建议 |

hatch-counter 早期的建议是：**一个付费客户服务群 + 试用客户单聊**。试用客户先不进群，避免看到老客户的问题产生顾虑，也避免群里混着还没决定买的人。

群里发版本更新通知，可以直接复用产品的更新日志。hatch-counter 的发版流程里，CI 已经会往一个企业微信群机器人发一条带更新日志的消息（`tools/workflow-notify`，用的是群机器人的 webhook 和 `markdown_v2` 格式）。同一段更新日志稍作改写（去掉开发者才关心的内容），就是给客户群的版本播报。群机器人能否加入含外部客户的群，以企业微信当前规则为准；不行的话就由你手动转发。

## 合规提醒

- 客户的聊天记录、标签、备注都是个人信息，处理时遵守《个人信息保护法》（见《国内合规实务》第 6 章）
- 企业微信的「会话内容存档」需要告知并取得对方同意，一人公司早期用不到，不要开
- 不要把客户聊天记录原样上传到不可信的 AI 服务做分析（《用 AI 撑起一人公司》第 4 章讲过社群摘要的做法）

## 本章要点

- To B 产品的私域容器选企业微信；个人微信只放熟客和同行，新线索一律进企业微信
- 没有主体也能用未认证的企业微信，但客户上限 100 人（含已删除）、客户群只能邀请 200 位客户；预计会超过时提前办主体
- 认证每次 300 元审核费、每年年审；认证后视后台情况为免费 2000 外部联系人规模或初始 5 万客户上限；单成员上限 2 万不能扩容
- 一个渠道一个「联系我」码，自动打标签、发对应欢迎语；`state` 不超过 30 字符，`config_id` 要存好
- 欢迎语做三件事：说明你是谁、回应他为什么来、给出下一步
- 用阶段标签当最简 CRM，但付费客户的关键信息要落在自己的系统里
- 成员群发每位客户每天 1 条、客户朋友圈每天最多展示 3 条；实际节奏远低于上限
- 早期一个付费客户服务群 + 试用客户单聊就够
